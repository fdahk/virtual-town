# 用户文本处理模块实施方案

> 模块定位：处理玩家输入文本，完成 query 改写、意图识别、上下文召回、结构化回复和行动决策

---

## 1. 设计目标

用户文本不能直接拼进 LLM prompt。系统需要理解“我刚才说的那个地方”“他在哪里”“你还记得吗”等模糊表达，并结合玩家角色、对话对象、当前场景和双方记忆生成合理回复。

输出也不能只是文本，还需要包含：

- NPC 回复文本。
- 情绪。
- 动作。
- 关系变化。
- 记忆写入。
- 后续 tool calling 行动。

---

## 2. 处理流程

```text
玩家输入文本
  ↓
输入清洗与安全检查
  ↓
Query 改写
  ↓
意图识别
  ↓
上下文召回
  ├── Redis 短期上下文
  ├── PostgreSQL 结构化记忆
  └── pgvector 语义召回
  ↓
Prompt 组装
  ↓
LLM 结构化回复
  ↓
Pydantic 校验
  ↓
执行 tool calls / 写记忆 / 更新关系
  ↓
返回前端
```

## 3. Query 改写

### 3.1 输入

```json
{
  "player_agent_id": "player_001",
  "target_agent_id": "npc_xiaofang",
  "scene_id": "scene_hobbs_cafe_inside",
  "raw_text": "你还记得他昨天点了什么吗？",
  "recent_dialogue": [
    { "speaker": "player", "text": "小王今天会来吗？" },
    { "speaker": "npc_xiaofang", "text": "他经常上午来买咖啡。" }
  ]
}
```

### 3.2 输出

```json
{
  "rewritten_query": "玩家询问小芳是否记得小王昨天在咖啡店点了什么。",
  "resolved_entities": [
    { "mention": "他", "entity_id": "npc_xiaowang", "confidence": 0.91 }
  ],
  "needs_memory_search": true
}
```

## 4. 意图识别

```json
{
  "intent": "ask_memory",
  "sub_intent": "ask_preference",
  "sentiment": "neutral",
  "urgency": "normal",
  "requires_action": false
}
```

意图枚举：

| intent | 说明 |
|--------|------|
| `chat` | 普通闲聊 |
| `ask_memory` | 询问过去事件 |
| `ask_location` | 询问地点/人物位置 |
| `request_action` | 请求 NPC 做某事 |
| `give_item` | 给予物品 |
| `trade` | 交易 |
| `comfort` | 安慰 |
| `threaten` | 威胁或挑衅 |
| `pet_animal` | 与动物互动 |

## 5. 上下文召回

### 5.1 Redis 短期上下文

召回：

- 当前对话窗口。
- 最近 10-30 分钟附近发生的事件。
- 当前场景中的可见实体。
- 对话对象当前情绪和行动。

### 5.2 PostgreSQL 结构化召回

召回：

- 双方关系。
- 已知偏好。
- 约定、承诺、任务。
- 最近重要事件。

### 5.3 pgvector 语义召回

对改写后的 query 做 embedding，召回相关记忆：

```sql
SELECT *
FROM memories
WHERE agent_id = :target_agent_id
ORDER BY embedding <=> :query_embedding
LIMIT 8;
```

最终排序：

```text
score =
  semantic_similarity * 2.0 +
  importance * 3.0 +
  recency * 0.5 +
  relationship_relevance * 1.5
```

## 7. API 设计

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/api/players/me/talk` | 玩家向 NPC 发送文本（正式入口；契约见 `数据模型与接口契约V1.md` §8.3） |
| `POST` | `/api/dialogue/rewrite-query` | 调试：只做 query 改写 + 意图 |
| `POST` | `/api/dialogue/retrieve-context` | 调试：召回上下文（多轮 + 记忆） |

### 7.1 玩家消息请求

```json
{
  "player_agent_id": "player_001",
  "target_agent_id": "npc_xiaofang",
  "text": "你还记得他昨天点了什么吗？",
  "scene_id": "scene_hobbs_cafe_inside"

```

## 8. 安全与兜底

| 情况 | 处理 |
|------|------|
| 用户输入过长 | 截断并提示 |
| 指代无法解析 | 追问用户“你指的是谁？” |
| 没有相关记忆 | NPC 如实回答不记得 |
| LLM 超时 | 使用规则回复 |
| 输出不符合 schema | 重试，仍失败则返回兜底文本 |
| 恶意/越权请求 | 拒绝执行世界修改 tool |

---

## 9. 验收标准

1. 用户可以与 NPC 对话。
2. 系统能改写含代词的 query。
3. 回复能利用 Redis、PG、pgvector 的上下文。
4. 回复包含文本、情绪、动作和记忆写入。
5. 对话结果能影响 NPC 后续行为。
