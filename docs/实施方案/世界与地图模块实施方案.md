# 世界与地图模块实施方案

> 模块定位：虚拟世界的空间、物理、环境和交互底座  
> 适用范围：室外地图、建筑内部地图、碰撞、环境后果、设施物品、动植物实体  
> 总体架构参考：`React版AI小镇实施方案.md`  
> **关键实现文件**：`backend/app/db/seed.py`、`frontend/public/assets/manifest/tilesets.manifest.json`、`frontend/src/game/scenes/TownScene.ts`

---

## 1. 设计目标

世界与地图模块不能只是“把角色画在地图上”。它必须表达一个符合现实逻辑的 2D 生活世界：

- 角色能在室外街区、自然区域、建筑内部之间切换。
- 地图上存在建筑、河流、树木、道路、家具、设施、动物、可交互物品。
- 物理规则可解释：墙不可穿越，家具会阻挡，河流无护栏时会触发落水状态，有护栏时阻挡。
- 建筑有内部空间，参考《星露谷物语》的室外大地图 + 室内房间模型。
- 动物不是装饰物，猫狗等动物与人类 NPC 一样属于 Agent，只是感知、行为工具和表达方式不同。

---

## 2. 技术选型审查

### 2.1 候选方案

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| React DOM/CSS Grid | 学习成本低，调试简单 | 大地图、动画、碰撞和摄像机性能差 | 不适合主地图 |
| Canvas 原生 API | 自由度高 | 需要自己实现地图、动画、资源管理 | 成本过高 |
| PixiJS | 渲染性能强，现代化 | 只是渲染器，地图、场景、碰撞要自建 | 可作为高级替代，但 MVP 不优先 |
| Phaser 3 | 2D 游戏完整引擎，支持 Tiled、场景、精灵动画、摄像机 | 不是 React 思维，需要桥接 | 推荐 |
| Godot Web Export | 游戏能力强 | Web 集成、React UI、后端同步复杂 | 不适合本项目主路线 |

### 2.2 最终选择

选择 **React + Phaser 3 + Tiled Map Editor**。

选择理由：

1. 本项目是 Web 产品，不是独立游戏客户端，React 负责 UI 最合适。
2. 地图和角色动画是典型 2D 游戏场景，Phaser 比 DOM 更合适。
3. Phaser 对 Tiled 地图、瓦片层、对象层、摄像机、精灵动画支持成熟。
4. 原版 Stanford 项目使用 Tiled/Phaser 思路，验证过可行性；但本方案不是照搬，而是将**地图语义和物理规则后端权威化**。
5. Phaser 只负责渲染与前端表现，真实碰撞、状态变化、危险判定由后端 World Service 负责，避免前后端状态不一致。

## 4. 世界模型设计

### 4.1 Scene

Scene 表示一个可运行空间，例如室外小镇、咖啡店内部、学校教室、玩家家中。

```json
{
  "id": "scene_town_outdoor",
  "name": "小镇室外",
  "type": "outdoor",
  "width": 120,
  "height": 80,
  "tile_size": 32,
  "tiled_map_url": "/assets/maps/town_outdoor.tmj"
}
```

### 4.2 Tile

Tile 是后端逻辑格子，不依赖前端渲染层。

```json
{
  "scene_id": "scene_town_outdoor",
  "x": 24,
  "y": 16,
  "terrain": "river",
  "walkable": true,
  "blocks_movement": false,
  "blocks_vision": false,
  "hazard_type": "deep_water",
  "hazard_level": 8,
  "tags": ["water", "danger"]
}
```

### 4.3 Location

Location 是有语义的地点，例如咖啡店、学校、河边、公园长椅。

```json
{
  "id": "loc_hobbs_cafe",
  "scene_id": "scene_town_outdoor",
  "name": "Hobbs Cafe",
  "type": "building",
  "bounds": { "x": 30, "y": 12, "width": 8, "height": 6 },
  "entry_tiles": [{ "x": 34, "y": 18 }],
  "open_hours": { "start": "08:00", "end": "22:00" },
  "tags": ["cafe", "social", "workplace"]
}
```

### 4.4 Portal

Portal 连接室外和建筑内部，是实现星露谷式地图模型的关键。

```json
{
  "id": "portal_hobbs_cafe_door",
  "from_scene_id": "scene_town_outdoor",
  "from_tile": { "x": 34, "y": 18 },
  "to_scene_id": "scene_hobbs_cafe_inside",
  "to_tile": { "x": 5, "y": 9 },
  "interaction_type": "auto_enter",
  "requires_permission": false
}
```

### 4.5 WorldObject

WorldObject 表示家具、设施、植物、护栏、门、桌椅、咖啡机等对象。

```json
{
  "id": "obj_cafe_coffee_machine",
  "scene_id": "scene_hobbs_cafe_inside",
  "name": "咖啡机",
  "type": "facility",
  "position": { "x": 8, "y": 3 },
  "size": { "width": 1, "height": 1 },
  "blocks_movement": true,
  "durability": 100,
  "available_interactions": ["make_coffee", "inspect", "clean"],
  "tags": ["coffee", "work_tool"]
}
```

## 5. 环境后果模型

世界不是静态地图，角色行为会触发后果。

### 5.1 Hazard

```json
{
  "id": "hazard_river_deep_water",
  "scene_id": "scene_town_outdoor",
  "area": [{ "x": 10, "y": 20 }, { "x": 11, "y": 20 }],
  "type": "deep_water",
  "trigger": "on_enter",
  "effects": [
    { "type": "set_status", "status": "drowning" },
    { "type": "reduce_stamina", "value": 30 },
    { "type": "emit_event", "event_type": "agent_fell_into_water" }
  ]
}
```

### 5.2 护栏逻辑

河流边界如果存在护栏对象，则护栏 tile 的 `blocks_movement=true`，角色无法进入河流。如果没有护栏，水域 tile 可进入但触发危险。

```text
角色尝试移动到目标 tile
  ↓
WorldService 检查是否有阻挡物
  ↓
如果阻挡：拒绝移动并返回 collision event
  ↓
如果可进入但有 hazard：允许移动并触发 hazard effects
```

## 8. 前端实现

### 8.1 Phaser 层职责

- 加载 Tiled 地图。
- 按 scene 切换地图。
- 渲染角色、动物、物品和气泡。
- 播放移动动画和交互动画。

- 地点信息面板。
- NPC / 动物状态面板。

- 调试层开关，例如显示碰撞层、危险区、路径线。

## 9. 验收标准

1. 室外地图和至少 3 个建筑内部地图可以相互切换。
2. NPC 和玩家无法穿墙、穿家具。
3. 河流无护栏处进入会触发落水/溺水状态。
4. 狗、猫能在地图上自主移动，并对玩家靠近/点击产生反应。
5. 前端可开启调试层查看碰撞、危险区、可交互对象。
6. 世界状态以后端为准，刷新页面后状态可以恢复。

## 10. 建筑与环境建模规范

> 本节是新增建筑、环境、物品时必须遵守的操作规范，基于现有实现提炼而来。  
> **所有新建筑/场景的数据均在 `backend/app/db/seed.py` 中定义**，前端自动从后端 API 读取，无需修改前端代码。

---

### 10.1 坐标系与基本单位

| 概念 | 值 | 说明 |
|------|-----|------|
| 逻辑格单位 | 1 tile | 地图中所有坐标均为整数格坐标 |
| 渲染像素/格 | 32 px (`DISPLAY_TILE`) | 前端将 1 格渲染为 32×32 px |
| 室外地图尺寸 | 40×30 格 | `OUTDOOR_W=40, OUTDOOR_H=30` |
| 室内地图尺寸 | 16×12 格 | `INDOOR_W=16, INDOOR_H=12`（所有室内场景统一大小） |
| 坐标原点 | 左上角 (0, 0) | x 向右增大，y 向下增大 |

---

### 10.2 地形类型（terrain）规范

地形类型决定图块的视觉呈现和物理属性。所有地形必须在 `tilesets.manifest.json` 的 `terrain_map` 中注册 Kenney Tiny Town 图块索引。

#### 室外地形

| terrain 值 | 物理属性 | 说明 | 图块索引 |
|-----------|---------|------|---------|
| `grass` | walkable | 默认草地 | 0 |
| `road` | walkable | 道路（垂直 x=19,20；水平 y=14,15） | 40 |
| `bridge` | walkable | 桥（河流上方，x=12–16，y=4–5） | 43 |
| `river` | walkable + hazard `deep_water` level=8 | 可进入但触发溺水状态 | 255（兜底蓝色） |
| `cafe_ext` | blocks_movement | 咖啡店建筑外墙 | 60 |
| `school_ext` | blocks_movement | 学校建筑外墙 | 52 |
| `grocery_ext` | blocks_movement | 杂货店建筑外墙 | 60 |
| `flower_ext` | blocks_movement | 花店建筑外墙 | 62 |
| `home_ext` | blocks_movement | NPC 住宅外墙 | 48 |
| `cafe_door` / `school_door` / `grocery_door` / `flower_door` / `home_door` | walkable + entry | 建筑底行门片，兼作传送门触发格 | 74–78 |

#### 室内地形

| terrain 值 | 物理属性 | 说明 |
|-----------|---------|------|
| `wall` | blocks_movement + blocks_vision | 室内外圈墙壁 |
| `floor` | walkable | 室内地板 |

> **新增地形规则**：必须同时在 `tilesets.manifest.json` 的 `terrain_map` 中添加对应图块索引，否则前端回退为纯色色块。

---

### 10.3 建筑完整建模要求

每一栋**可进入**建筑必须由以下 6 个组件完整组成，缺一不可：

```
完整建筑 = 室外 Location（外壳）
         + 室外 block_rect 图块（视觉阻挡）
         + 室外 door_tile（walkable 门片，传送门触发格）
         + 室内 MapScene（空间容器）
         + 室内 MapTile（地板+墙壁）
         + Portal × 2（进门 + 出门）
         + 室内 Location（房间语义）
         + WorldObject（家具）
```

#### 10.3.1 室外建筑图块规范

在 `build_outdoor_tiles()` 中通过 `block_rect` + `set_tile` 组合定义：

```python
# 1. 铺建筑主体（全部 blocks_movement=True）
block_rect(x0, y0, x1, y1, "home_ext")

# 2. 在底行中心设置可走门片（建筑入口的视觉和传送门触发格）
door_x = x0 + (x1 - x0) // 2
door_y = y1  # 底行
set_tile(door_x, door_y, terrain="home_door", walkable=True, blocks_movement=False, tags=["entry"])
```

**坐标约束**：
- `x0`、`y0`：建筑左上角格坐标
- `x1 = x0 + width - 1`（包含端点）
- `y1 = y0 + height - 1`（包含端点）
- 门片格 = `(x0 + width // 2, y0 + height - 1)`（底行正中）
- 室外入口格 = `(x0 + width // 2, y0 + height)`（门片正下方一格，用于出门落点）
- **禁止**：建筑矩形不能与道路（y=14,15 或 x=19,20）、河流（y=4,5）或其他建筑重叠

#### 10.3.2 室外 Location 规范

```python
Location(
    id="loc_<name>",
    scene_id=OUTDOOR_ID,
    name="建筑显示名称",
    location_type="building",         # 必须为 "building"
    bounds={"x": x0, "y": y0, "width": w, "height": h},
    entry_tiles=[{"x": door_x, "y": door_y}],  # 门片格（与 Portal from_tile 一致）
    open_hours={"start": "HH:MM", "end": "HH:MM"},  # 可选
    tags=["<类型>"],
)
```

> `entry_tiles` 必须指向**门片格**（`y0+height-1`），而不是门前一格（`y0+height`）。NPC 将把门片格作为导航目标。

#### 10.3.3 室内 MapScene 规范

```python
MapScene(
    id="scene_<name>_inside",
    name="<建筑名>·<房间名>",
    scene_type="indoor",              # 必须为 "indoor"
    width=INDOOR_W,                   # 固定 16
    height=INDOOR_H,                  # 固定 12
    tile_size=32,
    description="一句话描述室内氛围",
)
```

所有室内场景通过 `build_indoor_tiles("home"|"cafe"|"school"|"grocery")` 生成瓦片：
- 外圈（x=0, x=15, y=0, y=11）为 `wall`（blocks_movement=True）
- 内部（x=1–14, y=1–10）为 `floor`（walkable=True）
- 底行中心 `(entry_x, 11)` 强制保留为可走出口格（同时作为 Portal out 的 `from_tile`）

当前所有室内 scene 的 `entry_x = 7`（固定底行中心列）。

#### 10.3.4 Portal 规范（进 + 出成对）

```python
# 进门：室外门片格 → 室内到达点
Portal(
    id="portal_<name>_in",
    from_scene_id=OUTDOOR_ID,
    from_tile={"x": door_x, "y": door_y},      # 门片格
    to_scene_id="scene_<name>_inside",
    to_tile={"x": 7, "y": 9},                   # 室内到达点（固定偏上位置）
    interaction_type="auto_enter",
    requires_permission=False,
    name="<建筑名>·进门",
)
# 出门：室内出口格 → 室外入口格
Portal(
    id="portal_<name>_out",
    from_scene_id="scene_<name>_inside",
    from_tile={"x": 7, "y": 11},                # 室内底行出口（固定）
    to_scene_id=OUTDOOR_ID,
    to_tile={"x": door_x, "y": door_y + 1},     # 室外门前一格（入口格）
    interaction_type="auto_enter",
    requires_permission=False,
    name="<建筑名>·出门",
)
```

**关键约束**：
- `interaction_type` 必须为 `"auto_enter"`（踩到立即触发，无需额外确认）
- `to_tile`（进门室内落点）固定为 `(7, 9)`，保留底行 `y=11` 作为出口
- 出门落点为 `door_y + 1`（门前一格），确保落在可走格而不是建筑内部

#### 10.3.5 室内 Location 规范

```python
Location(
    id="loc_<name>_interior",
    scene_id="scene_<name>_inside",
    name="<建筑名>（室内）",
    location_type="room",             # 必须为 "room"
    bounds={"x": 1, "y": 1, "width": 14, "height": 10},  # 固定：去掉外圈墙后的内部区域
    entry_tiles=[{"x": 7, "y": 8}],  # 室内中央偏下，NPC 停留目标点
    tags=["<类型>_interior"],
)
```

室内 Location 的 `entry_tiles` 用于 NPC 在室内时的导航停留点，应位于室内中央活动区（非墙壁格）。

---

### 10.4 仅装饰建筑（无室内场景）

若建筑**不需要玩家/NPC 进入**（如花店目前作为纯装饰），只需：
1. `block_rect` 铺室外建筑图块
2. 设置 door tile（walkable，但**不添加 Portal**）
3. 添加室外 `Location`（`location_type="building"`）

此类建筑没有室内 MapScene 和 Portal，NPC 只能导航到门前，不会进入。如后续需要可进入，按 10.3 补齐完整组件。

---

### 10.5 NPC 日程与建筑的关联规范

NPC 的 `schedule_template` 中 `location_id` 的选取规则：

| 活动类型 | 应使用的 location_id | 说明 |
|---------|---------------------|------|
| `sleep`、`home`、`rest` | `loc_<name>_interior` | 在家里，必须用室内 Location |
| `work`、`shopkeep`、`clinic` | `loc_<name>_interior` | 在工作场所室内 |
| `work_from_home`、`study`（在家） | `loc_<name>_interior` | 在自己家室内 |
| `relax`、`walk`（室外） | 室外 Location ID | 如 `loc_river_bench`、`loc_park` |
| `morning`、`breakfast`、`dinner`（在家） | `loc_<name>_interior` | 在家准备/用餐，使用室内 Location |

> **原则**：凡是活动实际发生在建筑内部的，`location_id` 必须指向 `_interior` 版本，而非室外建筑 Location。这样 NPC 会通过传送门进入室内，而不是站在门口。

---

### 10.6 NPC 初始位置规范

NPC 的初始位置（`AgentState.x, y`）必须满足以下条件：

1. **不在建筑主体内**：建筑主体格（`blocks_movement=True`）不可作为初始位置
2. **推荐位置**：家门外入口格（`door_y + 1`），即门片正下方一格（walkable）
3. **检查方法**：在 `npc_positions` 字典中，确保坐标对应的格不在任何 `block_rect` 的范围内

```python
# 正确示例：初始位置 = 家门外入口格
npc_positions = {
    "npc_xiaofang": (OUTDOOR_ID, (3, 27)),   # 小芳家 door=(3,26)，入口格=(3,27) ✓
}
# 错误示例：初始位置在建筑内部
npc_positions = {
```

### 10.7 世界物品（WorldObject）建模规范

#### 分类

| `object_type` | 说明 | 典型 `blocks_movement` |
|--------------|------|----------------------|
| `furniture` | 桌椅、书架、床、柜台等 | True（大件）/ False（凳子） |
| `facility` | 咖啡机、工作台等设施，可触发功能交互 | True |
| `barrier` | 护栏、栅栏，纯物理阻挡 | True |
| `decoration` | 花盆、摆设，不阻挡 | False |

#### 位置规范

- 所有家具坐标在**室内有效格范围**内（x=1–14, y=1–10），不得放在墙壁格（x=0, x=15, y=0, y=11）
- 不得覆盖室内出口格 `(7, 11)` 和到达格 `(7, 9)`
- 大件（w≥2 或 h≥2）且 `blocks_movement=True` 时，应留出宽度≥1 的走道供 NPC 通行

#### 标准可交互动作（`available_interactions`）

| 动作 | 适用场景 |
|------|---------|
| `inspect` | 通用，任何物品均可添加 |
| `sleep` | 床（必须） |
| `sit` | 椅子、长椅 |
| `work` / `use_computer` | 工作台、电脑 |
| `study` | 书桌 |
| `make_coffee` / `clean` | 咖啡机 |
| `browse` | 货架 |
| `tend` | 花架、植物 |

### 10.8 室外环境元素规范

#### 道路

- **垂直主干道**：x=19, x=20（贯通南北，不可放置建筑）
- **水平主干道**：y=14, y=15（贯通东西，不可放置建筑）
- 道路格 `terrain="road"`，始终 `walkable=True`，`tags=["road"]`

#### 河流与桥

- 河流位置：y=4, y=5（贯通全图宽度 x=0–39）
- 桥：x=12–16，y=4–5（`terrain="bridge"`，walkable，无 hazard）
- 非桥处河流：`hazard_type="deep_water"`, `hazard_level=8`
- 护栏（WorldObject）沿 y=3 放置于 x=0–11 和 x=17–39（阻止从陆地直接跳河）

| 河流 | y=4, y=5，全 x |
| 现有建筑（含 1 格缓冲） | 见下表 |

**当前建筑占用坐标（含门片入口格）**：

### 10.9 新增建筑操作清单

新增一栋建筑时，按以下顺序完成所有步骤：

- [ ] **选址校验**：确认 `bounds` 不与现有建筑、道路、河流重叠（见 10.8 禁止区）
- [ ] **tilesets.manifest.json**：若使用新地形名，在 `terrain_map` 中添加图块索引
- [ ] **`build_outdoor_tiles()`**：添加 `block_rect` 和 `set_tile`（门片）
- [ ] **`seed()` - 室外 Location**：`location_type="building"`，`entry_tiles` 指向门片格
- [ ] **`seed()` - 室内 MapScene**：`scene_type="indoor"`，尺寸 16×12
- [ ] **`seed()` - 室内 MapTile**：调用 `build_indoor_tiles("<kind>")`（需在 dict 中注册 kind）
- [ ] **`seed()` - 室内 Location**：`location_type="room"`，`entry_tiles` 指向室内停留点
- [ ] **`seed()` - Portal × 2**：进门 `from_tile`=门片格，出门 `from_tile`=`(7, 11)`
- [ ] **`seed()` - WorldObject**：添加室内家具，坐标在 x=1–14, y=1–10 内
- [ ] **NPC 日程**：相关 NPC 的 `schedule_template` 中将 `location_id` 指向 `_interior`
- [ ] **NPC 初始位置**：确保在建筑主体格之外（入口格或其他可走格）
- [ ] **重新播种**：运行 `scripts/seed.sh` 验证无报错
