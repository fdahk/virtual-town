## 1. 重构动机

当前记忆系统的 4 个核心痛点（PM 调研得出，详见 `开发记录.md` §34）：

| # | 痛点 | 当前实现 | 期望 |
|---|------|----------|------|
| 1 | **不是所有经历都进记忆** | `event_projector` `importance < 4` 直接丢弃；黑名单较广 | 所有 NPC 经历的事件 / 对话都进记忆 |
| 2 | **不重要记忆直接归档丢弃** | TTL 24h → `importance < 7` 全部 `scope='archived'`，不再参与默认检索；无任何合并 | 越不重要越批量合并成 summary，原文保留为证据 |
| 3 | **重要记忆没有深化** | 只有 TTL 时升级 long_term；没有"反复回想 → 产生新感悟"的循环 | 重要记忆周期性被回顾，产生新 thought 记忆，原记忆 importance ↑ |
| 4 | **last_accessed_at 字段没用上** | 检索时不更新，访问强化失效 | 命中即刷新，自然带出"被频繁回忆 → 不易忘"的语义 |

## 2. 新模型：四态记忆生命周期

```text
┌────────────┐    ┌────────────┐    ┌──────────────┐    ┌────────────┐
│  WORKING   │ →  │ SHORT_TERM │ →  │  LONG_TERM   │ →  │  RUMINATED │
│  30 min    │    │  24 仿真h  │    │  永驻        │    │ (importance│
│  低重要度  │    │  默认入口   │    │  imp ≥ 7     │    │  +1 后回到 │
│  TTL 自动 │    │            │    │  或被深化   │    │ long_term) │
│  忘记     │    │            │    │             │    │            │
└────────────┘    └────────────┘    └──────────────┘    └────────────┘
                         │                  ▲
                         │ TTL 过期         │ 重要记忆抽样
                         ▼                  │ rumination
                  ┌─────────────┐           │
                  │  ARCHIVED   │ ──────────┘
                  │  (待合并)    │
                  └─────────────┘
                         │ daily consolidation
                         ▼
                  ┌─────────────┐
                  │ CONSOLIDATED│   原文 scope 改这里，summarized_into_id
                  │             │   指向 long_term summary 记忆
                  └─────────────┘
                         │   evidence_memory_ids
                         ▼
                  ┌─────────────┐
                  │  SUMMARY    │   memory_type='summary' scope='long_term'
                  │ (long_term) │   importance ≤ 5
                  └─────────────┘
```

### 2.1 scope 状态字典（DB 字符串字段）

| scope | 创建来源 | TTL | 检索默认包含 |
|-------|---------|-----|------------|
| `working` | 自动投影低重要度事件、低 importance 工具记忆 | 30 仿真分钟 | ✅ |
| `short_term` | 大多数业务路径写入 | 24 仿真小时 | ✅ |
| `long_term` | TTL 升级（imp ≥ 7）/ 反思 / 日结 / 沉思衍生 | ∞ | ✅ |
| `archived` | TTL 降级（imp < 7）尚未合并 | ∞ | ❌（仅显式查证据时） |
| `consolidated` | **新**：archived 被某条 summary 收录后改这里 | ∞ | ❌（永远不进默认检索；保留作证据） |

### 2.2 新增字段

`memories` 表：

| 字段 | 类型 | 用途 |
|------|------|------|
| `summarized_into_id` | `String(64)` nullable | 指向收录此条的 summary memory.id；非 NULL 即代表"已被合并" |
| `last_accessed_at` | 已存在 | 本次起：search 命中即刷新 |

> 不修改 `scope` 列定义类型（保持 `String(16)`）；`consolidated` 是字符串值，不必 enum。

## 3. 三大模块

### 3.1 模块 A：所有经历都进记忆

**`event_projector` 调整**：

| 配置 | 旧 | 新 |
|------|----|----|
| `MEMORY_PROJECTION_DEFAULT_MIN_IMPORTANCE` | 4 | **2** |
| 黑名单 `_BLOCK_EVENT_TYPES` | 含 `dialogue.message_created` 等 11 项 | 仅保留无 actor 的纯系统事件 |
| 默认 `memory_type` | `thought` | 阶段 importance 分层：< 4 → `thought` working / ≥ 4 → `event` short_term |

**对话记忆补全**：
- NPC-NPC 对话循环：除了 `_wrap_up` 写一条 chat，**每一条 dialogue.npc_to_npc_message 也分别写一条 chat 记忆给两位参与者**（importance=2~3，scope=working，最高 short_term）。
- 玩家 ↔ NPC：保留现有 talk 写入。
- 反思任务的 `event|chat` 召集器自然识别这些短期记忆。

**MemoryService.write 完整支持 `working` scope**：
- TTL 30 仿真分钟（之前 short_term 24h，现在 working 走更短窗口）。
- 写 Redis 镜像（key_short_memory）以便决策 fast-path 拿最近的"鸡毛蒜皮"。

### 3.2 模块 B：低重要度批量合并 → summary

**新任务**：`memory_consolidation`（在 `daily_reflection` 之后排队）

**算法**：

```python
async def consolidate(agent_id, world_time):
    # 1. 取最近 7 仿真天的 archived 且未合并 (summarized_into_id IS NULL)
    rows = SELECT FROM memories WHERE
        agent_id=? AND scope='archived' AND summarized_into_id IS NULL
        AND created_at > now - 7d ORDER BY created_at
    if len(rows) < 3: return

    # 2. 按主题分桶：keywords[0] / subject / 默认 'misc'
    buckets = group_by(rows, key=lambda m: m.keywords[0] or m.subject or 'misc')

    # 3. 每桶 ≥3 条才合并
    for theme, members in buckets.items():
        if len(members) < 3: continue
        summary = await llm_summarize(members)        # prompt 见下
        new_mem = ms.write(memory_type='summary',
                           scope='long_term',
                           importance=min(5, max(m.importance for m in members) + 1),
                           description=summary,
                           keywords=[theme],
                           evidence_memory_ids=[m.id for m in members])
        # 4. 把原条 scope 改 consolidated + 设 summarized_into_id
        for m in members: m.scope='consolidated'; m.summarized_into_id=new_mem.id
```

**LLM prompt 模板**（新增 `prompts/memory_consolidation/v1.jinja2`）：
- 输入：N 条原文 + 主题词
- 输出：简短的"过去一周的 X 主题印象..."（最多 200 字），不要重复列举每条原文，要"提炼模式"。

**降级策略**：LLM 不可用 → rule_consolidate：直接拼接前 3 条 description 截断到 200 字 + 主题前缀。

### 3.3 模块 C：重要记忆深化 → rumination

**新任务**：`memory_rumination`（每 NPC 24 仿真小时一次）

**算法**：

```python
async def ruminate(agent_id, world_time):
    # 1. 抽样 importance ≥ 7、last_accessed_at < 24h 前的长期记忆
    candidates = SELECT FROM memories WHERE
        agent_id=? AND scope='long_term' AND importance >= 7
        AND (last_accessed_at IS NULL OR last_accessed_at < now - 24h)
        ORDER BY random() LIMIT 5
    if len(candidates) < 2: return

    # 2. LLM 重新感悟
    new_thought = await llm_ruminate(agent_profile, candidates)   # prompt 见下

    # 3. 产出 thought + evidence
    ms.write(memory_type='thought', scope='long_term',
             importance=clamp(4, max(c.importance for c in candidates), 6),
             description=new_thought,
             evidence_memory_ids=[c.id for c in candidates])

    # 4. 强化原记忆
    for c in candidates:
        c.importance = min(10, c.importance + 1)
        c.last_accessed_at = now
```

**LLM prompt 模板**（新增 `prompts/memory_rumination/v1.jinja2`）：
- 输入：Agent profile + N 条重要记忆
- 输出：第一人称"我最近经常想起 X，让我意识到 Y..."的短反思。
- 严格 JSON：`{"thought": "...", "importance": 4-6}`。

**入队**：与 `_enqueue_reflect_batch` 在同一个调度点；新方法 `_enqueue_rumination_batch`，每 NPC 24 仿真小时阈值。

### 3.4 模块 D：last_accessed_at 启用

**`MemoryService.search`** 命中后：
```python
async def search(...) -> list[MemorySearchResult]:
    ...  # 现有逻辑
    scored = scored[:limit]
    # 新增：记忆访问强化
    if scored:
        await session.execute(
            update(Memory).where(Memory.id.in_([r.memory.id for r in scored]))
            .values(last_accessed_at=now)
        )
        # 不立即 commit；交给上层
    return scored
```

**recency_score 公式扩展**（可选 PR4 调权）：
- 现有：`exp(-Δ_created / 24h)`
- 改为：`max(exp(-Δ_created / 168h), exp(-Δ_accessed / 24h))`
  → 频繁回忆的旧记忆继续保持高权重。

## 9. 影响面 / 性能

- **DB 写入**：每场对话从 2 条 → ~10 条（每轮 2×5 + wrap 2）。短期消耗，TTL 30 分钟自动归零。
- **DB 增长**：`memories` 表每天约 1k → 5k 条；7 天后 archived 大部分会被合并成 1-2 条 summary，净增长可控。
- **LLM 调用**：consolidation + rumination 每 NPC/天 ≈ 2 次 LLM；6 NPC × 2 = 12 次/天，低于反思任务量。
- **检索**：search 默认仍只看 `working/short_term/long_term`，archived/consolidated 不进；性能不退化。
