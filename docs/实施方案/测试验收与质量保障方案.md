# 测试验收与质量保障方案

> 模块定位：定义 AI 小镇正式开发中的测试策略、验收标准、性能指标和风险兜底。

---

## 1. 设计目标

本项目功能复杂，必须用明确的测试和验收标准控制质量。重点不是追求测试数量，而是覆盖高风险链路：

- 地图碰撞和危险区。
- 仿真 tick 和状态同步。
- LLM tool calling 解析和兜底。
- NPC 记忆写入和检索。
- 玩家与 NPC/动物交互。
- 前后端接口一致性。

---

## 3. 必测核心链路

### 3.1 世界与地图

| 用例 | 预期 |
|------|------|
| 玩家走向墙壁 | 移动被拒绝 |
| 玩家走进无护栏河流 | 触发 `drowning` 状态 |
| 玩家走向有护栏河流 | 被护栏阻挡 |
| 玩家进入咖啡店入口 | scene 切换到咖啡店内部 |
| 点击咖啡机 | 触发物品交互事件 |

### 3.2 仿真循环

| 用例 | 预期 |
|------|------|
| AI 任务超时 | 世界继续运行，Agent 进入 fallback 行动 |
| 暂停仿真 | world tick 停止 |
| 单步执行 | 只推进一个 tick |
| 多 Agent 同时移动 | 前端收到增量 delta |

### 3.3 NPC 与记忆

| 用例 | 预期 |
|------|------|
| NPC 看到玩家进入咖啡店 | 写入短期记忆 |
| 玩家与 NPC 对话 | 双方记忆写入 |
| 查询“小王喜欢什么咖啡” | 从语义记忆召回相关事件 |
| 一天结束 | 生成 daily summary |

### 3.4 用户文本处理

| 用例 | 预期 |
|------|------|
| “他昨天点了什么？” | query 改写解析“他”的指代 |
| 无相关记忆 | NPC 如实回答不记得 |
| 用户超长输入 | 截断或拒绝 |
| LLM 返回非 JSON | 重试，失败后 fallback |

---

## 4. 性能验收

MVP 性能目标：

| 指标 | 目标 |
|------|------|
| 前端地图渲染 | 50-60 FPS |
| WebSocket delta 延迟 | 本地 < 200ms |
| 6 人类 NPC + 4 动物运行 | 无明显卡顿 |
| 普通 world tick | < 50ms |
| LLM 决策超时兜底 | 5-15 秒内 |
| 页面首次加载 | < 3 秒，本地开发环境可放宽 |

---

## 5. 接口一致性验收

1. 后端 OpenAPI 能正常生成。
2. 前端类型由 OpenAPI 生成。
3. WebSocket 消息有固定 `type` 和 `payload`。
4. 所有 LLM tool schema 有单元测试。
5. 数据库 migration 可从空库跑到最新版本。

---

## 6. 演示验收脚本

正式展示时必须能跑通以下故事线：

1. 玩家创建角色进入小镇。
2. 玩家移动到咖啡店门口并进入室内。
3. 小芳在咖啡店工作。
4. 玩家点击小芳并询问“小王喜欢喝什么？”。
5. 小芳根据记忆回答小王喜欢美式咖啡。
6. 玩家抚摸小芳的狗豆豆。
7. 豆豆根据性格和关系做出开心反应。
8. 玩家走到无护栏河边并进入水域，触发落水/溺水状态。
9. 所有关键事件能在事件日志和记忆面板中看到。

---

## 7. 风险兜底

| 风险 | 兜底 |
|------|------|
| LLM 不稳定 | JSON Schema 校验 + fallback |
| 地图资源制作慢 | 先做小地图 + 3 个室内空间 |
| pgvector 调试复杂 | 先结构化检索，后补向量召回 |
| Phaser 与 React 状态冲突 | EventBus 单向通信 |
| 性能不足 | 活跃区域裁剪 + 增量广播 |

---

## 8. 验收标准

1. 核心演示脚本能连续跑通。
2. 所有必测链路有测试或手动验收记录。
3. 关键失败场景不会导致系统崩溃。
4. 本地一键启动后可复现同样演示结果。
