# AI 小镇开发规范

## 1. 文档优先

1. 每个核心模块必须先有实施方案文档，再进入编码。
2. 模块文档必须包含接口、数据模型、WebSocket 事件、tool calling 契约和边界兜底。
3. 不需要单独写日志文档，但关键业务流程必须在对应模块文档中说明事件流和可观测字段。
4. 任何接口、数据模型或 tool calling 变更，都必须同步更新前后端文档，确保两端对齐。

## 2. 模块化与组件化

1. 禁止单文件承担过多职责。前端组件、状态、API、游戏系统必须拆分清楚。
2. 后端按领域拆分为 world、simulation、agent、memory、player、conversation、llm 等模块。
3. 模块之间只能通过明确接口通信，禁止跨模块直接读写内部状态。
4. 公共类型放在统一 schema / types 目录，避免多处重复定义。

## 3. 代码质量

1. 代码需要写清楚注释，但注释应解释复杂逻辑、业务约束和设计原因，不写无意义注释。
2. 复杂函数必须拆分，单个函数只承担一个清晰职责。
3. 禁止通过不断叠加 if/else 的方式修补设计问题。修改前先评估模块设计是否需要重构。
4. 对关键逻辑必须写单元测试或最小验证脚本，尤其是路径规划、记忆检索、tool calling 解析、用户文本处理。

## 4. 接口与模型一致性

1. 后端 Pydantic 模型、数据库模型、OpenAPI 文档、前端 TypeScript 类型必须保持一致。
2. 优先使用 OpenAPI 生成前端 API 类型，避免手写类型漂移。
3. WebSocket 消息必须有版本、类型和 payload schema。
4. LLM 输出必须使用 JSON Schema / Pydantic 校验，不允许依赖自然语言字符串切割。

## 5. 边界、兜底与性能

1. 所有外部调用必须有超时、重试和失败兜底，包括 LLM、Embedding、数据库、Redis。
2. LLM 输出错误不能导致仿真崩溃，必须回退到规则行为。
3. 前端渲染帧率、后端世界 tick、AI 决策 tick 必须解耦，避免 AI 调用阻塞世界运行。
4. 大量 NPC、动物、世界事件同时存在时，要使用空间索引、增量广播、活跃区域裁剪等策略。

## 6. 数据流与状态管理

1. 必须保证数据流清晰，数据分层存储、数据获取有全局统一的接口或方法，数据消费处按照统一方式获取，不允许组件或业务模块各自直接向后端随意请求。
2. 后端是权威世界状态来源，前端只能展示、缓存和发起用户意图，不能在本地自行判定最终世界结果。
3. 前端数据获取统一走 `api/` 服务层；React 组件禁止直接调用 `fetch`、`axios` 或 WebSocket。
4. 服务端状态缓存推荐使用 TanStack Query，游戏运行态和 UI 选中态使用 Zustand，二者职责必须区分。
5. Phaser 不直接请求后端，不直接修改 React 状态；Phaser 与 React 只能通过 EventBus 和 store adapter 通信。
6. WebSocket 只负责增量事件和运行态同步；页面初始化和详情查询走 REST API。
7. 数据写入必须通过命令式接口，例如 `movePlayer`、`interactWithObject`、`sendDialogueMessage`，禁止组件直接拼接口参数。
8. 所有跨模块数据结构必须来自共享 schema 或 OpenAPI 生成类型，禁止重复手写。

## 7. 安全、权限与内容边界

1. 所有玩家操作必须后端校验权限、距离、状态和目标合法性，不能信任前端。
2. LLM tool calling 必须经过 ToolExecutor 校验，禁止 LLM 直接修改数据库或世界状态。
3. 用户输入文本必须做长度限制、基础安全过滤和内容边界处理。
4. API Key、数据库密码等密钥只能通过 `.env` 注入，禁止写入代码和文档示例真实值。
5. 对外部资源和美术资产必须记录 license，禁止使用来源不明或未授权素材。

## 8. 可观测性与错误处理

1. 后端必须有统一错误模型和错误码，前端根据错误码展示用户可理解的信息。
2. 核心链路必须有结构化日志，包括 simulation_id、agent_id、event_id、task_id。
3. LLM 调用必须记录模型名、耗时、是否重试、是否 fallback，但不能记录敏感密钥。
4. WebSocket 断开、重连、消息乱序必须有处理策略。
5. 关键任务失败必须进入事件系统或任务状态表，不能只打印到控制台。

## 9. Prompt、模型与工具版本管理

1. Prompt 模板必须文件化、版本化，禁止散落在业务代码中。
2. Tool schema 变更必须版本化，并同步更新 `ToolCalling工具契约V1.md`。
3. LLM 输出必须有测试样例，覆盖合法输出、格式错误、字段缺失、工具不存在等情况。
4. 模型切换必须通过配置完成，业务模块不能写死模型名。

## 10. 工程化

1. 必须提供 Docker Compose 启动 PostgreSQL、Redis、后端和前端。
2. 必须使用数据库迁移工具管理 schema，例如 Alembic。
3. 必须提供种子数据脚本，初始化地图、建筑、NPC、动物、关系网络和玩家默认角色。
4. 必须提供一键启动脚本，降低本地开发门槛。
5. `.env.example` 必须覆盖所有必需配置，真实密钥不得提交到代码仓库。
6. 开发任务必须能追溯到对应方案文档、接口契约或产品需求，禁止无文档新增核心能力。
