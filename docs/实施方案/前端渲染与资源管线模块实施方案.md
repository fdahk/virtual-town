# 前端渲染与资源管线模块实施方案

> 模块定位：React UI、Phaser 游戏渲染、Tiled 地图资源、精灵动画和前后端事件桥接。

---

## 1. 设计目标

前端需要同时满足“产品界面”和“2D 世界渲染”两类需求：

- React 负责 UI、面板、表单、调试工具。
- Phaser 负责地图、角色、动物、物品、动画和摄像机。
- Tiled 负责地图制作和对象层标注。
- 前后端通过 REST + WebSocket 同步状态。
- 视觉资源必须通过 asset manifest 管理，不能在业务代码里散落硬编码图片路径。

建筑、人物、动物、室内外 tileset 的资源来源、授权和 manifest 设计详见 `视觉资源与美术资产方案.md`。

---

## 2. 工具选型

| 能力 | 工具 | 理由 |
|------|------|------|
| 前端框架 | React + TypeScript + Vite | 开发效率高，适合工程化 |
| 游戏渲染 | Phaser 3 | 完整 2D 引擎，支持 Tiled |
| 地图编辑 | Tiled Map Editor | 可视化制作瓦片地图和对象层 |
| 状态管理 | Zustand + TanStack Query | 仿真/选中 UI 态；REST 列表缓存 |
| API 类型 | openapi-typescript（可选） | `npm run gen:types` ← 后端 `/openapi.json` |
| UI 组件 | 原生 React（无 Ant Design / shadcn MVP 依赖） | 体量可控；后续可引入组件库 |

## 4. React 与 Phaser 分工

### 4.1 React 负责

- 页面布局。
- NPC/动物/玩家面板。
- 对话框。
- 记忆查看器。
- 仿真控制按钮。
- 调试图层开关。

### 4.2 Phaser 负责

- 根据 REST 返回的 `map_tiles` / scene 元数据在 Phaser 内构建 Tilemap（与后端权威网格对齐）。
- 可选：本地或 CI 导出 `.tmj`（`backend/app/tools/export_tmj.py`）供 **Tiled 对拍或美术迭代**；运行时**不要求**挂载 `frontend/public/assets/maps/*.tmj`。
- 渲染室外/室内 scene与 Portal 切换（由仿真态 `scene_id` 驱动）。
- 播放角色移动动画。
- 渲染对话气泡和表情。
- 摄像机跟随玩家。
- 接收地图点击和实体点击。

## 5. 事件桥接

React 和 Phaser 不直接互相修改状态，通过 EventBus 通信。

```ts
type GameEvent =
  | { type: "agent.move"; payload: AgentMovePayload }
  | { type: "agent.selected"; payload: { agentId: string } }
  | { type: "scene.change"; payload: { sceneId: string } }
  | { type: "debug.layer.toggle"; payload: { layer: string; enabled: boolean } };
```

流程：

```text
WebSocket 收到 simulation.delta（信封见契约）
  ↓
TownPage → worldStore 更新状态
  ↓
eventBus 派发 scene / agent / tick 事件（具体事件名以实现为准）
  ↓
TownScene 播放移动 / 切换场景 / 摄像机跟随
```

## 6. Tiled 资源规范

每张地图必须包含：

| Layer | 说明 |
|-------|------|
| `ground` | 地面 |
| `decoration` | 装饰 |
| `building` | 建筑外观 |
| `collision` | 碰撞层 |
| `hazard` | 危险区域 |
| `object` | 可交互对象 |
| `portal` | 建筑入口/出口 |
| `spawn` | 出生点 |

对象层示例：

```json
{
  "name": "portal_hobbs_cafe",
  "type": "portal",
  "x": 1088,
  "y": 576,
  "properties": {
    "to_scene_id": "scene_hobbs_cafe_inside",
    "to_x": 5,
    "to_y": 9
  }
}
```

## 7. 资源命名规范

```text
frontend/public/assets/
├── manifest/                       # sprites / tilesets / portraits 三类 manifest JSON
├── tilesets/
│   └── kenney_tiny_town/
├── sprites/
│   ├── humans/
│   └── animals/
├── portraits/                      # AI 或其它来源立绘（按 manifest）
```

（可选）`maps/*.tmj`：由导出工具生成的对拍产物，仓库未强制存放；运行时以服务端瓦片为准。

业务代码只引用 `asset_id`，由资源加载层根据 manifest 解析真实路径。
LPC 分层合成在项目本地通过 `scripts/compose_lpc.py` 预生成最终 sprite sheet，运行时不再做合成。

## 9. 验收标准

1. 室内外场景可走通：Phaser 展示的网格与后端 `map_tiles` / 场景缓存一致。
2. WebSocket `simulation.delta` 能驱动 Phaser；人物走动使用 LPC/Kenney 精灵资源。
3. 点击 NPC/动物能打开 React 面板；对话面板显示 AI 生成立绘。
4. 调试层能显示碰撞、危险区、portal、对象层。
5. 地图资源命名和 Tiled layer 规范统一，所有资源通过 asset manifest 引用。
6. `scripts/fetch_assets.sh` 一键恢复外部资源；`CREDITS.md` 同步更新。
