# 实施方案目录与模块边界

> 目的：明确正式开发前必须具备哪些方案文档，避免模块遗漏、职责重叠和前后端契约不一致。

---

## 1. 结论

当前已有文档覆盖了主业务链路，但还不完整。AI 小镇不是单一前端项目，也不是单一 Agent 项目，它至少包含以下三类模块：

1. **业务核心模块**：世界、仿真、NPC、玩家、文本交互。
2. **工程基础模块**：数据库、存储、LLM/tool calling、接口、资源管线。
3. **质量保障模块**：测试、验收、性能、安全和可观测。

正式开发前，必须保证每个模块都有独立方案文档。总方案只做总览，不承载细节。

## 4. 每个模块文档必须包含

1. 模块目标和边界。
2. 技术选型与选择理由。
3. 具体工具使用方式。
4. 核心数据模型。
5. REST API / WebSocket / 内部服务接口。
6. LLM tool calling 契约，如果该模块涉及智能决策。
7. 失败兜底、边界情况、性能策略。
8. 验收标准。

---

## 5. 模块依赖关系

```text
前端渲染与资源管线
        ↓
世界与地图模块 ← 玩家与交互模块
        ↓              ↓
仿真循环设计模块 ← 事件系统与任务调度
        ↓              ↓
智能 NPC 与记忆模块 ← 用户文本处理模块
        ↓              ↓
LLM 与 Tool Calling 模块
        ↓
数据库与存储模块
```

---

## 6. 开发顺序建议

1. 数据库与存储模块。
2. 前端渲染与资源管线模块。
3. 世界与地图模块。
4. 仿真循环设计模块。
5. 事件系统与任务调度模块。
6. 智能 NPC 与记忆模块。
7. LLM 与 Tool Calling 模块。
8. 玩家与交互模块。
9. 用户文本处理模块。
10. 测试验收与质量保障。

实际编码可以并行，但接口和数据模型必须先定。
