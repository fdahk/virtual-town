# 安全权限与内容安全方案

> 模块定位：约束玩家操作、API 权限、LLM tool calling、用户输入、密钥和资源授权。

---

## 1. 设计目标

即使 MVP 是本地演示项目，也不能默认信任前端和 LLM。所有会改变世界状态的操作都必须在后端校验。

---

## 2. 玩家操作安全

玩家操作包括：

- 移动。
- 进入建筑。
- 点击 NPC。
- 点击动物。
- 物品交互。
- 发送文本。

后端必须校验：

1. 玩家是否存在。
2. 玩家是否在当前 simulation。
3. 目标是否存在。
4. 目标是否在可交互距离内。
5. 玩家当前状态是否允许操作。
6. 操作是否被地图、物品或权限阻挡。

前端只负责提示，不能作为权限依据。

---

## 3. Tool Calling 安全

LLM 输出的 tool call 必须经过：

```text
ToolRegistry 查找
  ↓
参数 schema 校验
  ↓
权限校验
  ↓
世界状态校验
  ↓
ToolExecutor 执行
```

禁止：

- LLM 直接写数据库。
- LLM 直接生成 SQL。
- LLM 直接设置 Agent 坐标。
- LLM 调用未注册工具。

---

## 4. 用户文本安全

### 4.1 输入限制

| 项目 | 限制 |
|------|------|
| 单条消息长度 | MVP 建议 500 字以内 |
| 连续发送频率 | MVP 建议 1 秒 1 条 |
| 空消息 | 拒绝 |
| 超长消息 | 截断或提示用户缩短 |

### 4.2 内容边界

需要处理：

- 恶意命令注入。
- 让 NPC 执行越权行为。
- 要求泄露系统 prompt。
- 要求修改数据库或密钥。
- 与小镇无关的大段内容。

处理策略：

- 不执行越权 tool。
- NPC 可以在角色语气下拒绝。
- 系统不暴露 prompt、API key、内部数据。

---

## 5. API Key 与环境变量

1. `.env.example` 只能放占位符。
2. 文档中不得出现真实 API Key。
3. 后端日志不得打印 API Key。
4. 前端不得接触模型 API Key。
5. 所有模型调用必须从后端发起。

---

## 6. 资源授权安全

所有美术资源必须记录：

- 来源。
- 作者。
- license。
- 是否允许商用。
- 是否允许二次分发。

禁止使用：

- 商业游戏素材。
- 来源不明素材。
- 未确认授权的图片。

---

## 7. 错误响应安全

对外 API 不返回内部堆栈。

统一错误：

```json
{
  "code": "OUT_OF_RANGE",
  "message": "距离太远，无法交互。",
  "request_id": "req_001"
}
```

---

## 8. 验收标准

1. 玩家不能通过前端伪造请求穿墙或远程对话。
2. LLM 不能调用未注册工具。
3. 用户要求泄露 prompt 时系统拒绝。
4. 前端代码中没有模型 API Key。
5. 资源 manifest 中所有资源都有 license 信息。
