# 视觉资源与美术资产方案

> 模块定位：确认建筑、人物、动物、地图、UI 等视觉资源的处理方式，保证最终产品视觉效果统一、可落地、可替换、可授权。

---

## 1. 结论

本项目不建议从零手绘所有建筑、人物和动物资源。原因是周期长、成本高、对美术能力要求高，容易拖慢核心 AI 小镇功能开发。

推荐策略是：

```text
MVP 阶段：使用统一风格的现成 2D 像素风资源包
  ↓
二次整理：统一尺寸、命名、动画帧、Tiled 图层
  ↓
项目资产化：形成本项目自己的 assets 目录和 asset manifest
  ↓
后续优化：关键角色和建筑再逐步定制
```

最终产品风格建议选择 **像素风 / top-down 2D / 星露谷式小镇风格**。

---

## 2. 为什么选择现成资源包

### 2.1 自己从零制作的问题

如果自己完整制作，需要覆盖：

- 室外地形：草地、道路、河流、桥、护栏、树木、花草。
- 建筑外观：咖啡店、学校、杂货店、住宅、诊所、花店。
- 室内资源：墙壁、地板、桌椅、柜台、床、沙发、咖啡机、货架。
- 人物：6 个 NPC + 玩家，多方向行走动画。
- 动物：2 狗 2 猫，多方向行走/待机/反应动画。
- 特效：对话气泡、情绪、落水、互动提示。

这些工作量远超 MVP 重点。项目核心价值是 AI Agent 驱动的小镇，而不是从零画完整美术。

### 2.2 使用现成资源包的优势

- 快速达到完整视觉效果。
- 风格统一。
- 可以直接导入 Tiled 和 Phaser。
- 留出时间做 Agent、记忆、交互、仿真闭环。
- 后续可替换为自制资源，不影响系统架构。

## 3. 资源获取策略

### 3.1 可用资源来源

优先从以下渠道寻找资源：

| 来源 | 适合资源 | 注意事项 |
|------|----------|----------|
| itch.io | 像素风角色、建筑、室内外 tileset | 必须查看 license，优先 CC0 / 可商用 |
| OpenGameArt | 免费开源游戏资源 | 风格可能不统一，要筛选 |
| Kenney.nl | 高质量免费游戏资源 | 风格偏通用，license 友好 |
| CraftPix / GameDev Market | 付费游戏资源 | 需确认购买授权 |
| 原 Stanford Generative Agents 项目资源 | 参考地图和资源组织 | 不建议直接用于正式交付，除非确认 license |

### 3.2 授权要求

正式项目资源必须满足至少一种条件：

1. CC0 / Public Domain。
2. 明确允许个人/商业项目使用。
3. 已购买授权。
4. 作者明确允许使用并保留授权说明。

禁止：

- 直接从商业游戏中截取资源。
- 使用未授权的《星露谷物语》原始素材。
- 使用来源不明的网络图片。
- 使用不允许二次分发的资源并提交到仓库。

## 4. MVP 推荐资源组合

### 4.1 资源风格

统一选择：

```text
2D top-down pixel art
tile size: 32×32（最终决定，MVP 演示友好；原生为 16×16 的资源在 Phaser 中 scale 2x 引用）
角色方向：4 方向
动画：idle / walk 必须有，其他按需
```

### 4.1.1 美术方案拍板（战术层，2026-04-30）

本项目 MVP 不自行绘制像素资源，采用 **A+B+C 组合**：

| 角色 | 来源 | 授权 | 用途 |
|------|------|------|------|
| A 基础 tileset / 建筑 / 家具 / 部分动物 | **Kenney.nl · "Tiny Town"**（必选）+ `Tiny Dungeon` / `Pixel Platformer Pack` 按需 | **CC0**，无需署名 | 室内外地面、道路、河流、桥、树木、建筑外墙、柜台、桌椅、柜子、货架 |
| B 人物 / 动物 walk 动画 | **Universal LPC Spritesheet Generator** （sanderfrenken/Universal-LPC-Spritesheet-Character-Generator GitHub） | **CC-BY-SA 3.0 / GPL 3.0**，必须在 `CREDITS.md` 中署名并标注衍生品同协议 | 6 个人类 NPC + 玩家 4 方向 walk/idle 动画；猫狗 sprite |
| C NPC 对话头像（立绘） | **AI 生成**（GenerateImage 工具）+ 本项目自有 | 自有（由 AI 基于本项目提示词生成；项目自持） | ChatPanel 左侧、AgentPanel 顶部 |

理由：
- Kenney 提供干净 CC0 tileset，授权零风险。
- LPC 提供 Stardew 气质的人物 walk 动画和分层合成能力。
- 对话头像用 AI 生成的大立绘，是拉高"人物真实感"的最廉价且合规的手段。

授权管理：
- CC-BY-SA 衍生品要求：本项目因使用 LPC 而对这些资源衍生品同协议；项目代码本身不受影响（仅美术资源目录必须保留 LPC 相关 `CREDITS.md`）。
- AI 头像：记录生成时间与 prompt 版本，视为项目自有资产。
- 所有外部资源严禁未经确认来源就直接入库；下载脚本只允许使用记录在 manifest 中的 URL。

### 4.1.2 NPC 与资源的映射表

| Agent | LPC 组合（body + hair + clothes + accessory） | 头像 prompt 关键词 |
|-------|----------------------------------------------|-------------------|
| 小芳（咖啡店店员，热情外向） | light body + short_black hair + apron + brown_shoes | "cheerful female barista in apron, long black hair in ponytail, warm smile" |
| 小明（腼腆高中生） | light body + short_brown hair + school_uniform | "shy male high school student, glasses, school uniform, holding book" |
| 小王（内向程序员） | light body + short_brown hair + dark_jacket | "quiet male programmer, hoodie, tired eyes, holding coffee mug" |
| 林娜（冷静医生） | light body + medium_brown hair + white_coat | "composed female doctor, white coat, stethoscope, professional" |
| 陈伯（和善杂货店老板） | dark body + grey hair + vest | "kind elderly shopkeeper, grey beard, apron, warm smile" |
| 阿言（敏感花店店主） | light body + long_purple hair + pastel_dress | "artistic young florist, pastel dress, flower in hair, dreamy look" |
| 玩家（默认旅人） | 使用 LPC 默认 base，无装饰 | "friendly traveler with backpack, neutral style" |
| 豆豆（金毛） | LPC dog spritesheet (tan color) | "friendly golden retriever" |
| 黑黑（中华田园犬） | LPC dog spritesheet (black color) | "alert black watchdog" |
| 咪咪（三花猫） | LPC cat spritesheet (calico) | "independent calico cat sunbathing" |
| 小白（小白猫） | LPC cat spritesheet (white) | "timid white kitten" |

所有头像统一风格：16-bit JRPG / 星露谷风、上半身、居中、背景纯色或简单图案。
- **理想尺寸**：512×512（正方形）。
- **实际情况**：GenerateImage 工具默认输出 1536×1024（横版 3:2）。
  - 前端 CSS 已针对横版尺寸做了裁取适配（`object-fit: none; object-position: center 20%`），
    将显示窗口定位于图片中上区域（角色面部最可能所在的位置）。
  - 若后续手动重新生成并替换为 512×512 图片，CSS 无需更改（`center 20%` 对正方形图片同样合理）。
立绘文件存放在 `frontend/public/assets/portraits/humans/`、`.../animals/`。

### 4.2 必需资源清单

#### 地图 Tileset

必须包含：

- 草地。
- 土路/石板路。
- 水域/河流。
- 桥。
- 护栏。
- 树木。
- 花草。
- 建筑外墙和屋顶。
- 门和窗。

#### 室内 Tileset

必须包含：

- 墙。
- 地板。
- 桌椅。
- 柜台。
- 床。
- 沙发。
- 书架。
- 货架。
- 咖啡机。
- 诊所/学校相关物品。

#### 人物 Sprite

至少需要：

- 玩家默认角色 1 套。
- 6 个 NPC 角色。
- 每个角色至少 4 方向行走动画。

#### 动物 Sprite

至少需要：

- 狗 2 种颜色或造型。
- 猫 2 种颜色或造型。
- 每个动物至少 idle / walk 动画。
- 如果资源支持，额外使用 happy / scared / sleep 动画。

#### UI 资源

可以先使用 React 组件库，不强依赖像素风 UI。但建议有：

- 对话气泡。
- 互动提示图标。
- 情绪 emoji / icon。
- 状态图标，例如溺水、饥饿、开心、害怕。

## 5. 资源建模方式

### 5.1 AssetManifest

所有资源进入项目后，必须登记到 manifest，避免前端硬编码路径。

```json
{
  "id": "sprite_npc_xiaofang",
  "asset_type": "sprite",
  "entity_type": "human",
  "url": "/assets/sprites/humans/xiaofang.png",
  "frame_width": 32,
  "frame_height": 48,
  "animations": {
    "idle_down": { "frames": [0], "frame_rate": 1 },
    "walk_down": { "frames": [0, 1, 2, 3], "frame_rate": 8 },
    "walk_left": { "frames": [4, 5, 6, 7], "frame_rate": 8 },
    "walk_right": { "frames": [8, 9, 10, 11], "frame_rate": 8 },
    "walk_up": { "frames": [12, 13, 14, 15], "frame_rate": 8 }
  },
  "license": {
    "name": "CC0",
    "source": "https://example.com",
    "author": "asset_author"
  }
}
```

### 5.2 TilesetManifest

```json
{
  "id": "tileset_town_outdoor",
  "url": "/assets/tilesets/town_outdoor.png",
  "tile_width": 16,
  "tile_height": 16,
  "columns": 32,
  "source": "itch.io asset pack",
  "license": "CC0 or purchased"
}
```

### 5.3 Entity Visual

数据库中的 Agent 不直接写死图片路径，而是引用 asset id。

```json
{
  "agent_id": "npc_xiaofang",
  "visual": {
    "sprite_asset_id": "sprite_npc_xiaofang",
    "portrait_asset_id": "portrait_npc_xiaofang",
    "scale": 1,
    "default_direction": "down"
  }
}
```

## 7. Tiled 中的资源使用规则

### 7.1 Tile Size

MVP 推荐：

```text
地图逻辑 tile：32x32
原始资源 tile：16x16 或 32x32
如果原始资源是 16x16，可在 Phaser 中 scale 到 2x
```

统一约束：

- 同一张地图内 tile size 必须一致。
- 不同 tileset 可以来自不同资源包，但视觉风格必须接近。
- 室外和室内资源可以分开，但角色比例必须一致。

### 7.2 Object Layer

Tiled 中所有可交互对象必须带属性：

```json
{
  "object_id": "obj_cafe_coffee_machine",
  "object_type": "facility",
  "blocks_movement": true,
  "interactions": "make_coffee,inspect,clean"
}
```

这些属性会被导入脚本写入数据库。

## 8. 资源导入工具

需要实现一个资源导入脚本：

```bash
python -m app.tools.import_assets \
  --asset-dir frontend/public/assets \
  --manifest frontend/public/assets/manifest/assets.manifest.json
```

职责：

1. 校验资源文件是否存在。
2. 校验 manifest 字段完整。
3. 校验 license 信息是否填写。
4. 将 asset metadata 写入数据库。
5. 校验 Tiled map 引用的 tileset 路径是否有效。

## 9. 美术统一策略

### 9.1 风格原则

- 优先 pixel art。
- 角色比例统一。
- 建筑和室内家具透视统一。
- 动物尺寸与角色比例合理。
- 不混用明显冲突的高清手绘、卡通、像素资源。

### 9.2 颜色原则

- 小镇整体偏温暖、明亮。
- 危险区域要视觉上可识别，例如深色河流、警示标识。
- 可交互对象可以通过 hover 高亮或描边提示。

### 9.3 后续定制

MVP 后可定制：

- 主要 NPC 头像。
- 关键建筑招牌。
- 玩家角色换装。
- 特殊事件动画。

## 10. 原版资源是否可直接使用

原 Stanford Generative Agents 项目中的资源可以作为学习参考，尤其是：

- 地图结构。
- Tiled 图层组织。
- 人物 sprite 使用方式。
- 室内外小镇布局思路。

但不建议在正式交付中直接依赖原项目资源，除非已经确认其授权允许当前用途。

原因：

- 原项目资源来源涉及多个艺术作者。
- 不同资源可能有不同授权。
- 直接使用会让项目辨识度不足。

推荐做法：

1. 参考原项目布局和资源组织方式。
2. 自己选择明确授权的像素风资源包。
3. 用 Tiled 重新搭建本项目地图。
4. 在 README 或 credits 中记录资源来源和 license。

## 11. MVP 资源采购/整理任务

### 11.1 第一阶段落地清单（已拍板）

下载任务（由 `scripts/fetch_assets.sh` 完成，URL 固化在 `assets.manifest.json`）：

| 包 | 来源 | 预期获取内容 |
|----|------|--------------|
| Kenney · Tiny Town | <https://kenney.nl/media/pages/assets/tiny-town/> | tilemap（16×16，Phaser 内按 2x 缩放到 32×32）|
| Kenney · Roguelike/RPG Pack（备选补件） | <https://kenney.nl/assets/roguelike-rpg-pack> | 需要时取用 |
| LPC Universal Spritesheet | <https://github.com/sanderfrenken/Universal-LPC-Spritesheet-Character-Generator>（稀疏检出 `spritesheets/body/` + 所需 hair/clothes 子目录） | 人物分层 sprite（每层 832×1344，含 4 方向 walk + idle + 其它行 9 列 4 帧）|
| LPC Animals | 同上仓库 `spritesheets/animals/` | 猫狗 sprite |

生成任务（使用 GenerateImage）：

1. 6 张 NPC 立绘（每张独立调用，prompt 按 §4.1.2 映射表）。
2. 4 张动物立绘。
3. 1 张玩家默认立绘。
4. 生成物全部以 512×512 PNG 存到 `frontend/public/assets/portraits/`。

程序化产物：

1. `backend/app/tools/export_tmj.py`：从数据库 `map_tiles` / `locations` / `portals` / `world_objects` 导出 Tiled `.tmj` 到 `frontend/public/assets/maps/`。产出：
   - `town_outdoor.tmj`
   - `cafe_inside.tmj`
   - `school_inside.tmj`
   - `grocery_inside.tmj`
2. `frontend/public/assets/manifest/*.manifest.json`：asset / sprites / tilesets / portraits 四份。
3. 前端 `game/assets/loader.ts`：按 manifest 做 Phaser preload，失败资源走占位色矩形兜底，严禁 loader 失败导致白屏。

### 11.2 授权与署名流程

1. `CREDITS.md` 置于仓库根目录，必须列出：
   - 每一个外部资源包的名字、作者、授权、原始 URL。
   - LPC 衍生品的 CC-BY-SA 3.0 声明。
   - AI 生成头像的生成说明（工具、时间、prompt 摘要）。
2. `scripts/fetch_assets.sh` 在下载结束后追加 / 校验 `CREDITS.md`。
3. 未列入 manifest 的任何图片严禁进入 `frontend/public/assets/` 目录；CI 检查会阻止未登记文件。

## 12. 验收标准

1. 所有视觉资源都有明确来源和 license，均在 `CREDITS.md` 登记。
2. 所有人物/动物 sprite 都能在 Phaser 中播放 idle / 4 方向 walk 动画。
3. Tiled `.tmj` 能被 Phaser `load.tilemapTiledJSON` 正常加载，tileset 路径不丢失，室内外可切换。
4. 室外、室内、人物、动物整体视觉风格（俯视角像素 / 星露谷气质）统一。
5. `ChatPanel` 左侧显示当前对话 NPC 的对话立绘（裁取头部区域）；`AgentPanel` 顶部显示小头像（同样裁取）。
6. 游戏场景中 NPC 名称标签必须显示在 sprite 头部**上方**，不得遮挡头部。
   标签偏移量 = `frame_height × display_scale × origin_y + 6px`（动态计算，随 manifest 变化自适应）。
6. 资源路径通过 manifest 引用，业务代码禁止硬编码具体文件路径。
7. `scripts/fetch_assets.sh` 可重复执行且幂等，从零恢复环境时只需一条命令。
8. 资源加载失败时应用仍可运行（占位色兜底），并在控制台给出结构化报错，方便定位缺失资源。
