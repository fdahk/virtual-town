# 数据流与前端状态管理方案

> 模块定位：统一前端数据获取、缓存、运行态同步、Phaser 与 React 通信，避免数据流混乱。

---

## 1. 设计目标

本项目同时存在 REST、WebSocket、React UI、Phaser 游戏场景和本地状态。如果没有统一数据流规范，后续会很容易出现：

- 某些组件自己请求后端。
- Phaser 和 React 各自维护一套角色位置。
- WebSocket 消息和 REST 查询结果互相覆盖。
- UI 状态、服务端状态、游戏渲染状态混在一起。

因此必须明确数据分层和单向数据流。

---

## 2. 数据分层

| 数据类型 | 来源 | 前端存储 | 说明 |
|----------|------|----------|------|
| 服务端权威数据 | REST API | TanStack Query | Agent / World / Simulation / Memory / Relationship 等面板数据 |
| Phaser `/public` manifests | `/assets/*/manifest/*.json` | manifest 加载器内 `fetch` | 仅存资源索引，不进 Zustand |
| 实时运行态 | WebSocket | Zustand runtime slice | 坐标、当前状态、事件增量 |
| UI 临时状态 | 用户操作 | Zustand ui slice / React state | 当前选中 NPC、面板展开、调试层 |
| Phaser 渲染态 | Zustand + EventBus | Phaser Scene 内部 | sprite 实例、动画播放、摄像机 |
| 表单状态 | 用户输入 | React `useState` | MVP 创建玩家等表单未统一 Hook Form |

---

## 3. 数据流原则

```text
后端 REST / WebSocket
        ↓
api 层 / websocket client
        ↓
TanStack Query / Zustand
        ↓
React 组件 / EventBus
        ↓
Phaser 渲染
```

禁止反向依赖：

- React 组件禁止直接 `fetch`。
- Phaser 禁止直接请求后端。
- Phaser 禁止直接修改 React 组件 state。
- 业务组件禁止直接解析 WebSocket 原始消息。

## 4. 前端目录（与仓库一致）

```text
frontend/src/
├── api/
│   ├── http.ts              # fetch 封装、错误解析
│   ├── index.ts             # api.* — world / agents / player / simulation / observability …
│   └── websocket.ts         # ReliableSocket、simulationSocket、observabilitySocket
├── app/
│   └── App.tsx
├── pages/
│   ├── TownPage.tsx         # 挂载 simulation WS → worldStore → eventBus
│   └── observability/
├── stores/
│   └── worldStore.ts        # MVP 聚合「运行时仿真态 + UI」
├── game/
│   ├── eventBus.ts
│   ├── scenes/TownScene.ts
│   └── PhaserGame.tsx
├── components/
├── types/
│   ├── domain.ts
│   └── observability.ts    # （可选 openapi-typescript → types/api.ts）
└── main.tsx
```

拆分 `runtimeStore` / `uiStore` 仍为推荐演进方向；当前实现合并于 `worldStore`。

## 5. REST 数据获取

组件不能直接调用 API 文件，必须通过 hooks：

```ts
function useAgents() {
  return useQuery({
    queryKey: ["agents"],
    queryFn: agentApi.listAgents,
  });
}
```

组件使用：

```tsx
const { data: agents } = useAgents();
```

禁止：

```tsx
useEffect(() => {
  fetch("/api/agents");
}, []);
```

## 6. WebSocket 数据处理

**当前实现**：`TownPage.tsx`（及观测页各自的 effect）订阅 `simulationSocket` / `observabilitySocket`。收到消息后：

1. 更新 `worldStore`（仿真增量、事件列表等）。
2. 通过 `eventBus` 派发 `scene:change`、`agent:moved`、`simulation.tick` 等，供 `TownScene` 消费。

目标仍是「组件不直接解析底层 WebSocket JSON」：解析与版本字段集中在 `api/websocket.ts` 与上述订阅回调。

```ts
// 概念上等价；具体事件名以实现为准
gameEventBus.emit("simulation.delta", payload);
```

组件和 TownScene 不直接持有 `WebSocket` 实例。

## 7. Zustand Store 划分（现状与目标）

### 7.1 worldStore（当前）

MVP 将「仿真运行时 + 选中实体」等合并在 `stores/worldStore.ts`。职责上接近于下列 `RuntimeStore`，但字段名以实现为准。

### 7.2 目标拆分（演进）

仍可拆为：

```ts
interface RuntimeStore {
  worldTime: string;
  step: number;
  agentsById: Record<string, AgentRuntimeState>;
  recentEvents: WorldEvent[];
  applyDelta: (delta: SimulationDeltaPayload) => void;
}
```

### 7.3 uiStore（目标拆分 / 部分已并入 worldStore）

保存 UI 状态：

```ts
interface UIStore {
  selectedEntityId?: string;
  rightPanelOpen: boolean;
  debugLayers: {
    collision: boolean;
    hazard: boolean;
    portal: boolean;
  };
}
```

## 8. Phaser 通信

Phaser 只能通过 EventBus 接收指令：

```ts
gameEventBus.emit("agent.move", {
  agentId: "npc_xiaofang",
  to: { x: 12, y: 18 },
});
```

Phaser 点击实体后，也通过 EventBus 通知 React：

```ts
gameEventBus.emit("agent.selected", {
  agentId: "npc_xiaofang",
});
```

---

## 9. 数据写入命令

玩家行为必须封装成命令函数：

```ts
playerCommands.moveTo(tile);
playerCommands.interact(targetId, interactionType);
dialogueCommands.sendMessage(targetAgentId, text);
```

组件禁止自己拼请求：

```tsx
await fetch("/api/players/me/move", ...); // 禁止
```

---

## 10. 验收标准（目标）

1. 业务 API 经由 `src/api/http.ts` / `api.index`；避免在面板组件内手写裸 `fetch('/api/...')`。**例外**：Phaser 侧 manifest JSON 可由 `manifest.ts` 直接 `fetch` 静态路径。
2. Phaser Scene 不直接请求业务 REST。
3. 仿真 WS 解码入口集中在 **`api/websocket.ts` + 页面订阅回调**。
4. 服务端权威列表态优先 TanStack Query；tick 增量经 Zustand。
5. 玩家操作经 `api` 方法（等价于命令层）。
6. 断线重连后能经 REST 快照恢复后再接增量（参见 `ReliableSocket.setReconnectHook`）。
