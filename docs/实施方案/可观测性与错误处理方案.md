# 可观测性与错误处理方案

> 模块定位：统一错误模型、结构化日志、任务状态、LLM 调用记录、WebSocket 重连和问题定位能力。

---

## 1. 设计目标

AI 小镇包含仿真循环、WebSocket、LLM、数据库、Redis、Phaser 等多个环节。出错时必须能快速定位：

- 是前端渲染问题？
- 是 WebSocket 消息问题？
- 是后端仿真 tick 问题？
- 是 LLM 超时或格式错误？
- 是数据库/Redis 问题？

本模块不仅用于“出错后排查”，还必须提供一个**独立访问的研发观测平台**，让研发人员能完整观察 AI 小镇的运行过程：

- 世界正在发生什么事件？
- 每个 NPC / 动物当前在做什么？
- Agent 后端决策链路经过了哪些步骤？
- 玩家输入的一句话是如何被改写、召回、推理和执行的？
- LLM 调用了哪些 prompt、耗时多少、输出是否通过 schema？
- tool calling 是否成功执行？失败原因是什么？
- 记忆是如何写入、检索、遗忘和总结的？
- WebSocket 给前端推送了哪些状态变化？

可观测性平台的目标是：**让研发人员可以像看调试录像一样，还原系统每一步运行过程**。

---

## 2. 观测平台总体要求

### 2.1 独立访问地址

观测平台必须以独立地址访问，不能混在普通玩家 UI 中。

开发环境推荐：

```text
http://localhost:5173/observability
```

后端观测 API：

```text
http://localhost:8000/api/observability
```

后端观测 WebSocket：

```text
ws://localhost:8000/ws/observability/{simulation_id}
```

产品要求：

1. 普通玩家页面不展示研发调试信息。
2. 观测平台可以实时查看当前仿真。
3. 观测平台可以查看历史事件和历史 trace。
4. 观测平台支持按 simulation、agent、player、task、trace、时间范围筛选。
5. 观测平台不允许修改世界状态，除非明确进入 Debug Action 模式。

### 2.2 平台页面结构

观测平台至少包含以下页面：

| 页面 | 目标 |
|------|------|
| 总览 Dashboard | 查看仿真整体运行状态、tick、在线连接、错误率、LLM 耗时 |
| 世界事件流 World Events | 查看世界全部事件，支持按类型、地点、实体筛选 |
| Agent 运行视图 Agent Runtime | 查看每个 NPC / 动物的状态、位置、行动、情绪、记忆变化 |
| Agent 决策追踪 Decision Trace | 查看一次 Agent 决策从感知到 tool 执行的完整过程 |
| 玩家 Query 追踪 Query Trace | 查看玩家输入如何被清洗、改写、召回、回复和执行 |
| LLM 调用记录 LLM Calls | 查看模型、prompt 模板、耗时、重试、schema 校验和 fallback |
| Tool Calling 记录 Tool Calls | 查看工具调用参数、权限校验、执行结果和错误 |
| 记忆系统 Memory Inspector | 查看记忆写入、召回、分数、遗忘、每日总结 |
| 任务队列 Task Monitor | 查看异步任务状态、重试、失败、超时 |
| WebSocket 消息 WS Monitor | 查看后端推送给前端的 delta 和前端 ack 状态 |
| 错误中心 Error Center | 聚合所有错误，按严重程度和模块分类 |

## 3. 观测事件统一模型

所有可观测数据必须进入统一事件模型，不允许只依赖散乱日志。

```json
{
  "id": "obs_001",
  "simulation_id": "sim_001",
  "trace_id": "trace_001",
  "span_id": "span_001",
  "parent_span_id": null,
  "category": "agent_decision",
  "event_type": "agent.perceive.completed",
  "level": "INFO",
  "title": "小芳完成环境感知",
  "entity_id": "npc_xiaofang",
  "player_id": null,
  "task_id": "task_001",
  "world_step": 1024,
  "world_time": "2026-04-30T08:05:00+08:00",
  "duration_ms": 36,
  "payload": {
    "visible_entities": ["player_001", "animal_dog_doudou"],
    "visible_objects": ["obj_cafe_table"],
    "visible_events": ["evt_001"]
  },
  "created_at": "2026-04-30T08:05:01+08:00"
}
```

### 3.1 category 分类

```text
world_event
simulation_tick
agent_runtime
agent_decision
player_query
llm_call
tool_call
memory
task
websocket
error
performance
```

### 3.2 trace_id 要求

以下链路必须生成 trace_id：

1. 一次 world tick。
2. 一次 Agent 决策。
3. 一次玩家 query 处理。
4. 一次 LLM 调用。
5. 一次 tool calling 执行。
6. 一次 WebSocket delta 推送。

trace_id 必须在日志、事件、任务、LLM 调用、tool result、WebSocket 消息中贯穿。

## 4. 世界事件观测

世界事件流必须能完整展示虚拟世界发生了什么。

### 4.1 必须记录的世界事件

| 事件类型 | 示例 |
|----------|------|
| `agent.moved` | 小明从 A tile 移动到 B tile |
| `agent.entered_location` | 小芳进入咖啡店 |
| `agent.left_location` | 小王离开家 |
| `world.object_interacted` | 玩家使用咖啡机 |
| `world.hazard_triggered` | 玩家进入河流触发落水 |
| `animal.reacted` | 豆豆被抚摸后摇尾巴 |
| `dialogue.message_created` | 玩家和小芳产生一条对话 |
| `memory.created` | 小芳写入一条新记忆 |
| `relationship.updated` | 小芳对玩家好感 +1 |

### 4.2 World Events 页面要求

必须支持：

1. 实时事件流。
2. 按事件类型筛选。
3. 按 scene / location 筛选。
4. 按 agent / player / animal 筛选。
5. 点击事件查看 payload 详情。
6. 从事件跳转到相关 Agent、Memory、Decision Trace。

## 6. Agent 决策过程观测

Agent 决策是系统最重要的研发观测对象，必须完整暴露。

### 6.1 决策链路

一次 Agent 决策必须拆成以下 spans：

```text
agent_decision.start
  ↓
agent.perceive
  ↓
agent.retrieve_memory
  ↓
agent.build_context
  ↓
agent.llm_decide
  ↓
agent.validate_tool_calls
  ↓
agent.execute_tools
  ↓
agent.write_memory
  ↓
agent_decision.completed
```

### 6.2 Decision Trace 页面必须展示

| 区域 | 内容 |
|------|------|
| 基本信息 | agent、时间、触发原因、耗时、是否成功 |
| 感知结果 | 看到的人、动物、物品、地点、事件 |
| 召回记忆 | 每条记忆、分数、来源、是否被使用 |
| Prompt 上下文 | prompt template、上下文摘要、token 估算 |
| LLM 输出 | 原始结构化输出、schema 校验结果 |
| Tool Calls | 工具名、参数、校验、执行结果 |
| 状态变化 | 行动、情绪、路径、关系、记忆变化 |
| 错误与兜底 | 失败步骤、错误码、是否使用 fallback |

    "visible_entities": ["player_001"],

## 7. 玩家 Query 处理过程观测

玩家文本处理必须能完整还原。

### 7.1 Query Trace 链路

```text
player_query.received
  ↓
query.safety_check
  ↓
query.rewrite
  ↓
query.intent_detect
  ↓
context.retrieve_short_term
  ↓
context.retrieve_structured
  ↓
context.retrieve_vector
  ↓
prompt.build
  ↓
llm.generate_reply
  ↓
reply.validate_schema
  ↓
tool_calls.execute
  ↓
memory.write
  ↓
player_query.completed
```

### 7.2 Query Trace 页面必须展示

1. 玩家原始输入。
2. 清洗后的输入。
3. query 改写结果。
4. 代词/指代解析结果。
5. 意图识别结果。
6. 召回的 Redis 短期上下文。
7. 召回的 PostgreSQL 结构化上下文。
8. 召回的 pgvector 语义记忆及分数。
9. 发送给 LLM 的 prompt 模板和上下文摘要。
10. LLM 结构化回复。
11. 最终展示给用户的文本。
12. 触发的动作、情绪、关系变化和记忆写入。

- token_estimate。
- latency_ms。
- retry_count。

- schema_valid。

## 10. 记忆系统观测

记忆系统必须能观察：

1. 哪些事件写入了记忆。
2. 为什么写入长期记忆或短期记忆。
3. importance 如何计算。
4. embedding 是否生成成功。
5. 召回时哪些记忆被命中。
6. 每条记忆的 relevance / importance / recency 分数。
7. 一天结束时哪些短期记忆被遗忘、压缩或升级为长期记忆。

Memory Inspector 页面必须支持：

- 按 agent 查看全部记忆。
- 查看记忆来源事件。
- 查看召回分数。
- 查看 evidence memory ids。
- 查看 TTL 和遗忘状态。

## 11. 存储与保留策略

### 11.1 数据存储

推荐新增 PostgreSQL 表：

```text
observability_events
agent_decision_traces
player_query_traces
llm_call_records
tool_call_records
task_records
error_records
```

高频实时数据可先进入 Redis Stream，再异步落库。

### 11.2 保留周期

开发环境：

- 完整 trace 保留 30 天。
- 完整 prompt 可保留，但必须支持一键清理。

演示/生产环境：

- 完整 trace 保留 7 天。
- prompt 默认只保留摘要。
- 用户输入默认脱敏。

## 13. 安全与脱敏

观测平台是研发工具，必须防止泄露敏感信息。

禁止记录：

1. API Key。
2. 数据库密码。
3. Redis 密码。
4. 用户真实敏感信息。
5. 超长 prompt 全文默认展示。

必须提供：

1. prompt 脱敏。
2. 用户输入截断。
3. API Key 正则过滤。
4. 一键清理观测数据脚本。

## 14. 统一错误模型

```json
{
  "code": "TARGET_NOT_REACHABLE",
  "message": "目标地点当前不可达。",
  "request_id": "req_001",
  "details": {
    "target_location_id": "loc_hobbs_cafe"
  }
}
```

错误分类：

| 前缀 | 类型 |
|------|------|
| `WORLD_` | 地图、碰撞、危险区 |
| `AGENT_` | Agent 状态或行为 |
| `MEMORY_` | 记忆写入/检索 |
| `LLM_` | 模型调用 |
| `TOOL_` | tool calling |
| `PLAYER_` | 玩家操作 |
| `WS_` | WebSocket |
| `DB_` | 数据库 |

异步任务必须有状态：

```json
{
  "task_id": "task_001",

  "status": "running",

```

状态枚举：

```text

```

## 18. WebSocket 断线处理

前端必须支持：

1. 自动重连。
2. 重连后请求 REST 快照。
3. 根据快照恢复 runtime store。
4. 继续接收 delta。

流程：

```text
WebSocket disconnected
  ↓
show reconnecting
  ↓
retry with backoff
  ↓
GET /api/simulations/{id}/state
  ↓
replace runtime state
  ↓
resume delta handling
```

## 19. 前端错误展示

用户可见错误要友好：

| 错误 | 展示 |
|------|------|
| 距离太远 | “离得太远了，靠近一点再互动。” |
| 目标不可达 | “这里暂时过不去。” |
| LLM 超时 | “对方思考了一会儿，但没有回应。” |
| WebSocket 断开 | “正在重新连接小镇...” |

## 20. 验收标准

1. 可以通过 `http://localhost:5173/observability` 独立访问观测平台。
2. 观测平台 Dashboard 能展示当前 simulation 状态、world tick、在线连接、错误数、LLM 平均耗时。
3. World Events 页面能实时展示世界全部事件，并支持按事件类型、实体、地点筛选。
4. Agent Runtime 页面能查看每个 NPC / 动物的当前状态、行动、路径、情绪、需求、最近事件和最近记忆。
5. Agent Decision Trace 能完整展示一次决策的感知、记忆召回、上下文构建、LLM 输出、tool calling、状态变化和 fallback。
6. Player Query Trace 能完整展示玩家输入的清洗、query 改写、意图识别、上下文召回、LLM 回复、动作、记忆写入。
7. LLM Calls 页面能查看每次模型调用的 provider、model、prompt template、耗时、重试、schema 校验和 fallback。
8. Tool Calls 页面能查看每次工具调用的参数、权限校验、世界状态校验、执行结果和错误码。
9. Memory Inspector 能查看记忆写入原因、召回分数、TTL、遗忘或升级过程。
10. Task Monitor 能查看异步任务状态、重试、失败、超时。
