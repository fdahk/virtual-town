# 事件系统与任务调度模块实施方案

> 模块定位：统一管理世界事件、Agent 行动事件、异步任务、定时任务、重试和回放数据。

---

## 1. 设计目标

AI 小镇中所有变化都应该以事件形式记录和传播，例如：

- 玩家进入建筑。
- NPC 到达咖啡店。
- 狗被玩家抚摸。
- NPC 说了一句话。
- 角色掉进河里。
- LLM 决策任务完成。

事件系统负责：

- 记录事实。
- 触发后续任务。
- 推送前端。
- 写入记忆。
- 支持回放。

---

## 2. 工具选型

| 能力 | 工具 | 理由 |
|------|------|------|
| 异步任务 | Celery 或 RQ | 处理 LLM、总结、Embedding 等慢任务 |
| 消息/缓存 | Redis | 任务队列、短期状态、发布订阅 |
| 事件存储 | PostgreSQL | 可靠记录，支持回放和查询 |
| WebSocket 推送 | FastAPI WebSocket | 实时同步前端 |

MVP 可以先用 RQ，复杂度低；后续需要复杂调度时再换 Celery。

---

## 3. 事件模型

```json
{
  "id": "evt_001",
  "simulation_id": "sim_001",
  "event_type": "agent.entered_location",
  "source": "world_service",
  "actor_entity_id": "npc_xiaoming",
  "target_entity_id": null,
  "location_id": "loc_school",
  "scene_id": "scene_town_outdoor",
  "payload": {
    "description": "小明进入学校",
    "x": 42,
    "y": 18
  },
  "importance": 4,
  "created_at": "2026-04-30T08:00:00"
}
```

---

## 4. 事件类型

| 类型 | 说明 |
|------|------|
| `agent.moved` | 实体移动 |
| `agent.entered_location` | 进入地点 |
| `agent.left_location` | 离开地点 |
| `agent.action_started` | 行动开始 |
| `agent.action_finished` | 行动结束 |
| `dialogue.message_created` | 对话消息 |
| `world.object_interacted` | 物品交互 |
| `world.hazard_triggered` | 危险触发 |
| `animal.reacted` | 动物反应 |
| `memory.created` | 记忆创建 |
| `llm.task_started` | LLM 任务开始 |
| `llm.task_finished` | LLM 任务完成 |

---

## 5. 任务模型

```json
{
  "id": "task_001",
  "task_type": "agent_decision",
  "status": "pending",
  "priority": 5,
  "entity_id": "npc_xiaofang",
  "payload": {
    "reason": "current_action_finished"
  },
  "retry_count": 0,
  "max_retries": 2,
  "deadline_at": "2026-04-30T08:00:05"
}
```

---

## 6. 任务类型

| 任务 | 说明 |
|------|------|
| `agent_decision` | NPC/动物自主决策 |
| `generate_daily_plan` | 生成日计划 |
| `generate_dialogue_reply` | 生成对话回复 |
| `write_memory_embedding` | 生成记忆向量 |
| `daily_reflection` | 每日总结与反思 |
| `query_rewrite` | 用户文本改写 |
| `relationship_update` | 更新关系摘要 |

---

## 7. 事件流

```text
World Tick 产生事实事件
  ↓
EventStore 写入 PostgreSQL
  ↓
EventRouter 判断订阅者
  ├── WebSocket 推送前端
  ├── MemoryService 写记忆
  ├── AgentService 判断是否触发决策
  └── TaskQueue 投递异步任务
```

---

## 8. 幂等与重试

所有任务必须具备幂等 key：

```text
idempotency_key = f"{task_type}:{entity_id}:{simulation_step}"
```

重复任务处理规则：

1. 已完成任务不重复执行。
2. 运行中任务不重复投递。
3. 失败任务按 `max_retries` 重试。
4. 超时任务标记 failed，并触发业务兜底。

---

## 9. WebSocket 推送

事件不直接裸推给前端，而是转换为前端所需 delta：

```json
{
  "type": "simulation.delta",
  "payload": {
    "events": [
      {
        "event_type": "agent.entered_location",
        "description": "小明进入学校"
      }
    ],
    "entity_updates": []
  }
}
```

---

## 10. 验收标准

1. 所有世界变化都有事件记录。
2. 事件能驱动前端增量更新。
3. 事件能触发记忆写入。
4. LLM 等慢任务通过队列异步执行。
5. 任务失败有重试和兜底。
6. 事件流可用于回放。
