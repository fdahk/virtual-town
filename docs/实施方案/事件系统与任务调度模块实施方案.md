# 事件系统与任务调度模块实施方案

> 模块定位：统一管理世界事件、Agent 行动事件、异步任务、定时任务、重试和回放数据。

---

## 1. 设计目标

AI 小镇中所有变化都应该以事件形式记录和传播，例如：

- 玩家进入建筑。
- NPC 到达咖啡店。
- 狗被玩家抚摸。
- NPC 说了一句话。
- 角色掉进河里。
- LLM 决策任务完成。

事件系统负责：

- 记录事实。
- 触发后续任务。
- 推送前端。
- 写入记忆。
- 支持回放。

---

## 2. 工具选型

| 能力 | 工具 | 理由 |
|------|------|------|
| 异步任务 | Celery 或 RQ | 处理 LLM、总结、Embedding 等慢任务 |
| 消息/缓存 | Redis | 任务队列、短期状态、发布订阅 |
| 事件存储 | PostgreSQL | 可靠记录，支持回放和查询 |
| WebSocket 推送 | FastAPI WebSocket | 实时同步前端 |

MVP 可以先用 RQ，复杂度低；后续需要复杂调度时再换 Celery。

## 3. 事件模型

```json
{
  "id": "evt_001",
  "simulation_id": "sim_001",
  "event_type": "agent.entered_location",
  "source": "world_service",
  "actor_entity_id": "npc_xiaoming",
  "target_entity_id": null,
  "location_id": "loc_school",
  "scene_id": "scene_town_outdoor",
  "payload": {
    "description": "小明进入学校",
    "x": 42,
    "y": 18
  },
  "importance": 4,
  "created_at": "2026-04-30T08:00:00"
}
```

---

## 4. 事件类型

| 类型 | 说明 |
|------|------|
| `agent.moved` | 实体移动 |
| `agent.entered_location` | 进入地点 |
| `agent.left_location` | 离开地点 |
| `agent.action_started` | 行动开始 |
| `agent.action_finished` | 行动结束 |
| `dialogue.message_created` | 对话消息 |
| `world.object_interacted` | 物品交互 |
| `world.hazard_triggered` | 危险触发 |
| `animal.reacted` | 动物反应 |
| `memory.created` | 记忆创建 |
| `llm.task_started` | LLM 任务开始 |
| `llm.task_finished` | LLM 任务完成 |

---

## 7. 事件流

```text
World Tick 产生事实事件
  ↓
EventStore 写入 PostgreSQL
  ↓
EventRouter 判断订阅者
  ├── WebSocket 推送前端
  ├── MemoryService 写记忆
  ├── AgentService 判断是否触发决策
  └── TaskQueue 投递异步任务
```

---

## 8. 幂等与重试

所有任务必须具备幂等 key：

```text
idempotency_key = f"{task_type}:{entity_id}:{simulation_step}"
```

重复任务处理规则：

1. 已完成任务不重复执行。
2. 运行中任务不重复投递。
3. 失败任务按 `max_retries` 重试。
4. 超时任务标记 failed，并触发业务兜底。

---

## 9. WebSocket 推送

事件不直接裸推给前端，而是转换为前端所需 delta：

```json
{
  "type": "simulation.delta",
  "payload": {
    "events": [
      {
        "event_type": "agent.entered_location",
        "description": "小明进入学校"
      }
    ],
    "entity_updates": []
  }
}
```

---

## 10. 验收标准

1. 所有世界变化都有事件记录。
2. 事件能驱动前端增量更新。
3. 事件能触发记忆写入。
4. LLM 等慢任务通过队列异步执行。
5. 任务失败有重试和兜底。
6. 事件流可用于回放。

## 11. 边界异常处理与 NPC 容错机制

> 本节记录 2026-04-30 发现的 NPC 卡死 bug 根因分析及修复方案。

### 11.1 问题现象

NPC 小王长期处于以下僵死状态：
```
状态   IDLE
目标   路径不可达，等待
坐标   (19, 12)
```

### 11.2 根因分析

经代码与种子数据联合排查，共发现 **5 个相互叠加的 bug**：

#### Bug 1 — 种子数据：家庭入口格落在河流（主因）

`loc_home_xiaowang` 的 `bounds = {"x": 25, "y": 1, "width": 4, "height": 3}`，
entry_tile 按公式 `y = bounds.y + bounds.height = 1 + 3 = 4` 计算，
恰好等于地图中河流所在的 y=4（`hazard_type=deep_water`）。

`astar()` 在 `avoid_hazards=True` 时对目标格做预检：
```python
if not grid.is_walkable(*goal, avoid_hazards=avoid_hazards):
    return []  # 直接返回空，不展开搜索
```
因此路径查找在开始前就失败，每次 AI tick 均返回 `"路径不可达，等待"`。

#### Bug 2 — rule_agent：跨场景决策无路径

当日程目标（如 `loc_hobbs_cafe_interior`）位于另一个 scene 时，
`decide_human_action` 直接返回 `action_type="move_to_location"` 且 `path=None`。
`_apply_decision` 的 else 分支将状态设为 `INTERACTING`，NPC 原地不动，
无法穿越 portal 到达室内。

#### Bug 3 — rule_agent：A* 失败无恢复尝试

A* 失败时直接返回 `wait`，不尝试：
- 目标格周围的邻近可走格（目标本身被遮挡时）。
- BFS 解卡移动（NPC 自身位于死区时）。

下次决策 tick 到来时同样失败，形成死循环。

#### Bug 4 — engine：全局 AI 决策时钟

```python
last_dt = max(a.last_decision_at for a in self._agents.values() ...)
should_decide = (now - last_dt).total_seconds() >= ai_interval * 60
```
使用所有 Agent 的 `last_decision_at` 最大值作为触发条件。
任意一个 Agent 刚完成决策，全部 Agent 的决策都被阻塞，
卡死的 NPC 需等到最"安静"的窗口才能重新决策。

#### Bug 5 — engine：LLM 工具全失败时 `applied=True`

LLM 调用成功但所有工具均返回 `TARGET_NOT_REACHABLE`（结果列表非 None）时，
`applied = True`，规则兜底被跳过，NPC 仍然空路径。

### 11.3 修复方案

| 文件 | 修复内容 |
|------|---------|
| `db/seed.py` | `loc_home_xiaowang` bounds 移到 `{"x": 12, "y": 7, "width": 4, "height": 3}`（河流以南可达区域），初始位置改为 `(13, 8)` |
| `domain/simulation/rule_agent.py` | 新增 `_astar_with_fallback`：A* 失败时尝试目标周围 4 格内最近可走格 |
| `domain/simulation/rule_agent.py` | 新增 `_recovery_tile_bfs`：BFS 找最近可走邻格，让陷入死区的 NPC 先移出死区 |
| `domain/simulation/rule_agent.py` | 新增 `_find_portal_from_to`：跨场景时查找 portal，寻路到 from_tile，让引擎 `_on_agent_arrived` 自动传送 |
| `domain/simulation/rule_agent.py` | `decide_human_action` 新增 `portals_by_scene` 参数，跨场景决策生成有效路径 |
| `domain/simulation/engine.py` | `_decide_all` 移除全局 `should_decide`，改为每 Agent 独立检查 `last_decision_at` |
| `domain/simulation/engine.py` | `_decide_all` 在 LLM 结果中检查 `any(r.success for r in results)`，全失败则回退规则版 |
| `domain/simulation/engine.py` | `_apply_decision` 的 `wait` 分支设为 `WAITING`（原为 `IDLE`），与正常空闲状态区分 |
| `domain/simulation/engine.py` | `decide_human_action` 调用传入 `portals_by_scene=self._portals_by_scene` |

### 11.4 NPC 状态语义规范（更新后）

| 状态 | 含义 |
|------|------|
| `IDLE` | 初始 / 刚到达目的地，等待下一次决策 |
| `WAITING` | 主动等待（wait 动作）或暂时受阻（路径不通），将在下次 AI tick 重新决策 |
| `MOVING` | 正在沿路径移动 |
| `INTERACTING` | 到达目标地点，正在交互 |
| `CHATTING` | 对话中（不移动，不接受新决策） |
| `SLEEPING` | 睡眠中（不移动，不接受新决策） |

### 11.5 防御性设计原则

1. **entry_tile 必须通过 `is_walkable(..., avoid_hazards=True)` 校验**，种子数据和后续 Location 创建均需遵守。
2. **A* 寻路失败时不直接放弃**，先尝试目标邻格降级，再尝试 BFS 解卡移动，最后才返回 wait。
3. **跨场景移动必须生成到 portal 的有效路径**，不能返回无路径的 move_to_location。
4. **每个 NPC 独立计时**，单个 NPC 的决策冷却不影响其他 NPC。
5. **LLM 工具全失败 ≠ LLM 决策成功**，必须回退规则版确保 NPC 始终有行为。
