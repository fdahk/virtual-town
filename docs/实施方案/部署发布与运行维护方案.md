# 部署发布与运行维护方案

> 模块定位：规范本地开发、演示部署、环境配置、备份恢复、健康检查和发布流程。

---

## 1. 部署目标

MVP 优先支持本地 Docker Compose 一键启动。后续如需演示服务器部署，可以复用同一套容器。

---

## 2. 服务组成

```text
frontend    React + Vite
backend     FastAPI
postgres    PostgreSQL + pgvector
redis       Redis
worker      RQ/Celery worker
```

---

## 3. 环境变量

`.env.example` 必须包含：

```env
APP_ENV=development
BACKEND_PORT=8000
FRONTEND_PORT=5173

DATABASE_URL=postgresql+asyncpg://user:password@postgres:5432/virtual_town
REDIS_URL=redis://redis:6379/0

LLM_PROVIDER=dashscope
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_API_KEY=replace_me
LLM_CHAT_MODEL=qwen-plus
LLM_REASONING_MODEL=qwen-max
LLM_EMBEDDING_MODEL=text-embedding-v2
```

---

## 4. 一键启动流程

```bash
./scripts/dev.sh
```

脚本执行：

1. 检查 `.env`。
2. 启动 Docker Compose。
3. 等待 PostgreSQL 和 Redis ready。
4. 执行 Alembic migration。
5. 检查是否已有种子数据。
6. 无种子数据则执行 seed。
7. 输出访问地址。

---

## 5. 健康检查

后端提供：

| 路径 | 说明 |
|------|------|
| `/health` | 服务存活 |
| `/health/db` | 数据库连接 |
| `/health/redis` | Redis 连接 |
| `/health/llm` | LLM 配置检查，不执行昂贵调用 |

---

## 6. 数据备份

MVP 至少提供本地备份脚本：

```bash
./scripts/backup_db.sh
```

备份内容：

- PostgreSQL dump。
- seed data version。
- asset manifest。

不需要备份：

- node_modules。
- Python venv。
- 临时日志。

---

## 7. 发布流程

1. 运行测试。
2. 运行类型检查。
3. 执行数据库 migration。
4. 执行 seed 检查。
5. 启动服务。
6. 跑演示验收脚本。

---

## 8. 验收标准

1. 新机器 clone 项目后可通过 README 和 `scripts/dev.sh` 启动。
2. Docker Compose 启动所有服务。
3. 健康检查接口可用。
4. 数据库可备份和恢复。
5. 演示部署流程可重复执行。
