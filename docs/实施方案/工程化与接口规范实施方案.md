# 工程化与接口规范实施方案

> 模块定位：开发协作、数据库迁移、本地启动、接口契约和类型一致性

---

## 1. 设计目标

工程化目标是让项目可复现、可协作、可维护：

- 新成员能一键启动完整环境。
- 数据库 schema 有迁移记录。
- 初始地图、NPC、动物和关系能通过种子脚本生成。
- 前后端接口和类型保持一致。
- LLM tool calling 契约可测试、可版本化。

---

## 3. Docker Compose

服务：

```yaml
services:
  frontend:
    command: npm run dev
  backend:
    command: uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
  postgres:
    image: pgvector/pgvector:pg16
  redis:
    image: redis:7
```

---

## 4. 数据库迁移

后端使用 Alembic：

```text
backend/
├── alembic/
├── alembic.ini
└── app/db/models.py
```

规范：

1. 所有表结构变更必须生成 migration。
2. 禁止直接手改线上数据库。
3. 种子数据脚本不能代替 migration。
4. migration 文件需要写清楚变更目的。

---

## 5. 种子数据

种子数据必须包含：

- 室外主地图。
- 至少 3 个建筑内部地图。
- 建筑、设施、物品、河流、护栏、危险区。
- 6 个人类 NPC。
- 2 只狗、2 只猫。
- NPC/动物之间的初始关系。
- 默认玩家角色。

脚本：

```bash
./scripts/seed.sh
```

## 6. 接口契约

### 6.1 OpenAPI

FastAPI 自动生成 OpenAPI，但必须保持：

- 每个请求/响应都有 Pydantic schema。
- schema 字段要有注释。
- 不允许返回未定义的 `dict`。

### 6.2 前端类型生成

推荐使用：

```bash
openapi-typescript http://localhost:8000/openapi.json -o frontend/src/types/api.ts
```

前端 API 调用必须使用生成类型。

### 6.3 WebSocket 消息版本

```json
{
  "version": "1.0",
  "type": "simulation.delta",
  "payload": {}
}
```

## 7. Tool Calling 契约管理

所有 LLM tool schema 放在：

```text
backend/app/tools/schemas/
```

每个工具必须有：

- 名称。
- 描述。
- 参数 JSON Schema。
- 权限检查。
- 业务校验。
- 失败返回。

示例：

```json
{
  "name": "move_to_location",
  "description": "让 Agent 移动到指定地点",
  "parameters": {
    "type": "object",
    "properties": {
      "location_id": { "type": "string" },
      "reason": { "type": "string" }
    },
    "required": ["location_id", "reason"]
  }
}
```

---

## 8. 一键启动

```bash
./scripts/dev.sh
```

脚本职责：

1. 检查 `.env` 是否存在。
2. 启动 Docker Compose。
3. 执行数据库 migration。
4. 检查是否已有种子数据，没有则 seed。
5. 输出前端、后端、API 文档地址。

---

## 9. 验收标准

1. `docker compose up` 可启动依赖服务。
2. `./scripts/dev.sh` 可启动完整本地开发环境。
3. `./scripts/seed.sh` 可初始化完整演示世界。
4. 前端类型从 OpenAPI 生成。
5. 所有核心 tool calling schema 有文档和测试。
