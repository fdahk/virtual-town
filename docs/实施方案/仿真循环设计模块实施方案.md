# 仿真循环设计模块实施方案

> 模块定位：虚拟世界的时间推进、状态更新、事件调度和性能控制  
> 核心原则：渲染、世界运行、AI 决策三层解耦

---

## 1. 设计目标

仿真循环负责让世界持续运行，同时避免 LLM 调用和大量实体更新导致卡顿。它必须做到：

- 前端 60 FPS 渲染不被 AI 决策阻塞。
- 后端作为权威世界状态，统一处理位置、碰撞、事件和状态变化。
- NPC 和动物数量增加时仍能稳定运行。
- LLM 决策异步执行，未完成时 Agent 继续执行已有行动或进入兜底状态。

---

## 2. 三层时间模型

| 层级 | 推荐频率 | 负责内容 |
|------|----------|----------|
| Render Frame | 60 FPS | Phaser 动画、摄像机、插值渲染 |
| World Tick | 5-10 次/秒 | 移动、碰撞、状态衰减、事件触发 |
| AI Decision Tick | 游戏内 1-5 分钟/次，按需触发 | 计划生成、行为选择、对话、反思 |

关键原则：

1. Render Frame 只在前端执行，不参与权威逻辑。
2. World Tick 在后端执行，是位置和状态的唯一真相。
3. AI Decision Tick 异步执行，产出 Action Plan，不直接修改世界。

---

## 3. 后端仿真循环

```text
SimulationEngine.run()
  ↓
每个 World Tick：
  1. 读取输入队列：玩家移动、点击、交互
  2. 更新实体移动：沿路径推进
  3. 检查碰撞和危险区
  4. 更新状态：饥饿、体力、情绪、溺水等
  5. 触发世界事件
  6. 查找需要重新决策的 Agent
  7. 投递 AI 决策任务
  8. 应用已完成的 AI 决策结果
  9. 增量广播状态变化
```

---

## 4. Agent 行动状态机

每个 Agent 不应该每个 tick 都调用 LLM。推荐状态机：

```text
IDLE
  ↓ 需要目标
THINKING
  ↓ AI 返回 action
PLANNING_PATH
  ↓ 路径生成成功
MOVING
  ↓ 到达目标
INTERACTING
  ↓ 行动结束
IDLE
```

异常状态：

```text
BLOCKED       路径被阻挡
DROWNING      落水/溺水
SLEEPING      睡觉
WAITING       等待他人或事件
CHATTING      对话中
PANIC         受惊或危险状态
```

## 6. 性能策略

### 6.1 活跃区域

只对玩家附近和重要事件区域进行高频更新：

- 玩家所在 scene：高频更新。
- 玩家附近半径内实体：完整广播。
- 其他 scene：低频逻辑更新，只广播关键事件。

### 6.2 空间索引

后端维护 Grid Spatial Index：

```text
cell_key = f"{scene_id}:{x // cell_size}:{y // cell_size}"
```

用于快速查询：

- 附近 Agent。
- 附近物品。
- 碰撞对象。
- 感知范围内事件。

### 6.3 AI 任务队列

LLM 调用进入 Redis 队列：

```json
{
  "task_id": "decision_task_001",
  "type": "agent_decision",
  "agent_id": "npc_xiaoming",
  "priority": 5,
  "deadline_ms": 5000
}
```

任务超时：

- 超过 5 秒使用规则兜底。
- LLM 结果回来太晚则只作为下一次决策参考，不回滚世界状态。

## 7. 后端接口

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/api/simulations` | 创建仿真实例 |
| `POST` | `/api/simulations/{id}/start` | 开始 |
| `POST` | `/api/simulations/{id}/pause` | 暂停 |
| `POST` | `/api/simulations/{id}/resume` | 继续 |
| `POST` | `/api/simulations/{id}/step` | 单步推进 |
| `POST` | `/api/simulations/{id}/speed` | 修改速度 |
| `GET` | `/api/simulations/{id}/state` | 获取当前快照 |

## 9. 验收标准

1. 前端动画保持流畅，AI 决策慢时不阻塞地图渲染。
2. 玩家移动、NPC 移动、动物移动都以后端状态为准。
3. 6 个人类 NPC + 2 只狗 + 2 只猫同时运行无明显卡顿。
4. LLM 超时不会导致仿真崩溃。
5. WebSocket 只广播增量状态。
