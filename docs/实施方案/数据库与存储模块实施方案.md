# 数据库与存储模块实施方案

> 模块定位：统一管理结构化数据、向量记忆、短期上下文、仿真快照和资源元数据。

---

## 1. 设计目标

数据库是 AI 小镇的长期事实来源。必须先设计清楚数据模型，再进行开发。

本模块负责：

- 存储地图、建筑、物品、危险区。
- 存储 Agent、玩家、动物、关系、状态。
- 存储记忆、事件、对话、行动和仿真快照。
- 支持 pgvector 语义检索。
- 支持 Redis 短期上下文。
- 支持数据库迁移和种子数据。

---

## 2. 工具选型

| 能力 | 工具 | 理由 |
|------|------|------|
| 主数据库 | PostgreSQL 16 | 稳定，适合结构化关系数据 |
| 向量检索 | pgvector | 与 PostgreSQL 共库，降低系统复杂度 |
| ORM | SQLAlchemy 2.x | Python 生态成熟，支持异步 |
| Migration | Alembic | SQLAlchemy 标准迁移工具 |
| 缓存/短期记忆 | Redis 7 | 高速 TTL、队列、临时上下文 |
| 种子数据 | Python seed 脚本 | 与 ORM 模型一致 |

---

## 3. 数据分层

| 数据类型 | 存储 | 说明 |
|----------|------|------|
| 地图元数据 | PostgreSQL | scene、tile、location、portal、object |
| 实体档案 | PostgreSQL | NPC、动物、玩家基础资料 |
| 运行状态 | PostgreSQL + Redis | 最新状态入 Redis，关键快照入 PG |
| 短期记忆 | Redis | TTL 10 分钟到 24 小时 |
| 长期记忆 | PostgreSQL | 重要事件和总结 |
| 语义记忆 | PostgreSQL + pgvector | embedding 检索 |
| 事件流 | PostgreSQL | 回放和调试 |
| 资源文件 | 文件系统 / 对象存储 | 地图、sprites、tilesets |

## 4. 核心表设计

### 4.1 Agent

```sql
agents(
  id uuid primary key,
  entity_type text not null, -- human / animal / player
  name text not null,
  profile jsonb not null,
  visual jsonb not null,
  home_location_id uuid,
  created_at timestamptz not null
)
```

### 4.2 Agent State

```sql
agent_states(
  agent_id uuid primary key references agents(id),
  scene_id uuid not null,
  x int not null,
  y int not null,
  state text not null,
  emotion text,
  needs jsonb not null,
  current_action_id uuid,
  updated_at timestamptz not null
)
```

### 4.3 Memory

```sql
memories(
  id uuid primary key,
  agent_id uuid not null references agents(id),
  memory_type text not null, -- event / thought / chat / summary
  scope text not null, -- working / short_term / long_term
  subject text,
  predicate text,
  object text,
  description text not null,
  importance int not null,
  emotional_valence int default 0,
  embedding vector(1536),
  ttl_expires_at timestamptz,
  created_at timestamptz not null,
  last_accessed_at timestamptz
)
```

### 4.4 Relationship

```sql
relationships(
  id uuid primary key,
  from_agent_id uuid not null,
  to_entity_id uuid not null,
  familiarity int default 0,
  trust int default 0,
  affection int default 0,
  fear int default 0,
  summary text,
  updated_at timestamptz not null
)
```

### 4.5 World Scene / Location / Object

```sql
map_scenes(
  id uuid primary key,
  name text not null,
  scene_type text not null,
  width int not null,
  height int not null,
  tile_size int not null,
  tiled_map_url text not null
)
```

```sql
locations(
  id uuid primary key,
  scene_id uuid not null,
  name text not null,
  location_type text not null,
  bounds jsonb not null,
  entry_tiles jsonb,
  open_hours jsonb,
  tags text[]
)
```

```sql
world_objects(
  id uuid primary key,
  scene_id uuid not null,
  name text not null,
  object_type text not null,
  position jsonb not null,
  size jsonb not null,
  blocks_movement boolean default false,
  available_interactions text[],
  state jsonb not null

```

## 5. Redis Key 设计

```text
sim:{simulation_id}:state
agent:{agent_id}:runtime                 TTL 300s  — agent 运行态快照
agent:{agent_id}:short_memory            TTL 24h   — 短期记忆列表（最近 50 条）
agent:{agent_id}:unreachable             TTL 300s  — 不可达目标集合（location_id/entity_id）
dialogue:{conversation_id}:recent_messages TTL 2h — 对话窗口
world:{scene_id}:active_entities         TTL 300s  — 场景内活跃实体 id 集合
embed:{sha256(text)[:32]}                TTL 3600s — embedding 向量缓存
task:{task_id}:status                    TTL 300s  — 任务状态摘要（可观测性）
task:idempotency:{idempotency_key}                 — 任务幂等锁
```

**新增 key 说明**：

- `agent:{id}:unreachable`：当 `move_to_location` / `move_to_entity` 返回 `TARGET_NOT_REACHABLE`
  时写入目标 id（Set 类型）。下一次决策感知阶段读取并过滤不可达目标，防止 LLM 反复
  尝试相同不可达地点，TTL 与 `ai_tick_minutes` 对齐（5 分钟 = 300s）。

- `embed:{hash}`：EmbeddingService 返回的向量结果缓存，以文本 SHA-256 前 32 字符为 key，
  TTL 1 小时。相同文本重复 embed 请求命中缓存，避免重复 API 调用和延迟。

短期记忆示例：

```json
{
  "memory_id": "tmp_001",
  "description": "小芳刚才看到玩家走进咖啡店。",
  "created_at": "2026-04-30T10:00:00",
  "ttl_seconds": 3600
}
```

## 6. 迁移与种子数据

### 6.1 Alembic

```bash
cd backend
alembic revision --autogenerate -m "create agent and world tables"
alembic upgrade head
```

### 6.2 种子数据

```bash
python -m app.db.seed
```

种子数据必须包含：

- 室外地图和至少 3 个室内 scene。
- 6 个人类 NPC。
- 2 只狗、2 只猫。
- 初始关系。
- 默认玩家。
- 基础物品、建筑、危险区。

---

## 7. 验收标准

1. 数据库可通过 Alembic 一键迁移。
2. 种子数据可重复执行且幂等。
3. pgvector 可完成记忆语义召回。
4. Redis 短期记忆 TTL 正常过期。
5. 前后端数据模型与 OpenAPI schema 保持一致。
