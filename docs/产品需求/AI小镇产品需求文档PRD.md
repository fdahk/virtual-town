# AI 小镇产品需求文档 PRD

> 产品名称：AI 小镇  
> 产品形态：Web 版 2D AI 生活模拟小镇  
> 目标场景：腾讯程序员转正任务项目展示  
> 文档角色：产品经理视角，约束最终产品效果，防止开发偏离预期体验  
> 版本：V1.0

---

## 1. 产品一句话描述

AI 小镇是一个可在浏览器中运行的 2D 虚拟生活世界。玩家可以创建自己的角色进入小镇，与拥有记忆、性格、日程和自主行为的 NPC、猫狗等动物互动。小镇中的角色会根据时间、环境、关系和记忆自主行动、对话、成长，并对玩家行为产生持续反馈。

---

## 2. 产品愿景

本项目最终要展示的不是一个普通地图网页，也不是一个简单 AI 聊天窗口，而是一个“活着的小镇”。

用户进入网页后，应当感受到：

- 小镇有真实空间：街道、河流、建筑、室内房间、设施、家具、动物。
- 角色有生活节奏：起床、上学、工作、吃饭、回家、闲逛、聊天。
- NPC 不是脚本木偶：他们有性格、关系、记忆，会根据上下文做决定。
- 玩家不是旁观者：玩家可以移动、探索、对话、影响 NPC 和动物。
- 世界会记住事情：一次对话、一次帮助、一次惊吓动物，都会影响后续互动。

产品最终效果应接近“AI 驱动的星露谷式 2D 小镇模拟器”。

---

## 3. 目标用户

### 3.1 主要用户

项目评审人、导师、团队同事。

他们关心：

- 项目是否有完整产品形态。
- 技术架构是否合理。
- AI 能力是否真正融入业务，而不是简单套壳聊天。
- 是否有可演示、可解释、可扩展的闭环。

### 3.2 次要用户

普通体验用户。

他们关心：

- 打开网页是否能快速理解怎么玩。
- 小镇是否有趣。
- NPC 是否像真实角色。
- 对话和互动是否有持续影响。

---

## 4. 核心产品目标

### 4.1 必须达成

1. 用户能在 Web 页面中看到一个 2D 小镇。
2. 用户能创建并控制自己的玩家角色。
3. 小镇中有至少 6 个人类 NPC、2 只狗、2 只猫。
4. NPC 和动物能自主行动，不是静态装饰。
5. 玩家能进入建筑内部地图。
6. 玩家能与 NPC 对话。
7. 玩家能与动物互动。
8. 对话和交互会写入记忆。
9. NPC 后续行为或回答能体现记忆影响。
10. 前端能展示 NPC 当前行为、日程、记忆摘要、关系变化和事件日志。

### 4.2 展示重点

项目展示时，必须让评审清楚看到以下闭环：

```text
人物设定
  ↓
自主计划
  ↓
地图行动
  ↓
玩家/NPC/动物交互
  ↓
事件产生
  ↓
记忆写入
  ↓
后续行为或回答变化
```

## 5. 产品边界

### 5.1 本期要做

- 单人玩家体验。
- Web 版 2D 小镇。
- 室外大地图 + 至少 3 个建筑内部地图。
- 6 个人类 NPC。
- 2 只狗、2 只猫。
- NPC 日程、行动、对话、记忆。
- 玩家移动、点击、对话、动物互动。
- 基础现实规则：碰撞、建筑入口、河流危险、护栏阻挡。
- 事件日志和记忆查看。

### 5.2 本期不做

- 多人在线。
- 复杂经济系统。
- 战斗系统。
- 大型开放世界。
- 高级地图编辑器。
- 25 个以上 NPC 的大规模仿真。
- 完整任务系统和成就系统。
- 商业化用户体系。

## 6. 核心体验路径

### 6.1 首次进入

用户打开网页后，应看到：

1. 项目标题和简短说明。
2. 创建角色入口。
3. 可输入角色名称、性格、外貌描述和背景。
4. 创建完成后进入小镇。

体验要求：

- 用户 1 分钟内知道自己可以在小镇中移动和互动。
- 不需要阅读复杂说明即可开始体验。

### 6.2 探索小镇

用户进入小镇后，应看到：

- 2D 小镇地图。
- 玩家角色位于出生点。
- 附近有 NPC、建筑、动物或可交互设施。
- 顶部显示当前小镇时间。
- 侧边栏显示当前选中对象信息。
- 底部或侧边显示事件日志。

用户可以：

- 点击地图移动。
- 使用键盘移动。
- 点击建筑入口进入室内。
- 点击 NPC 查看信息或发起对话。
- 点击动物进行互动。
- 点击物品查看或交互。

### 6.3 与 NPC 对话

用户靠近 NPC 后点击 NPC，打开对话框。

用户输入：

```text
小王喜欢喝什么？
```

系统应：

1. 判断玩家和 NPC 距离是否允许对话。
2. 根据 NPC 记忆和当前上下文生成回答。
3. 展示 NPC 回复文本。
4. 同时展示 NPC 情绪或动作，例如微笑、思考。
5. 将这次对话写入记忆。
6. 可能更新玩家与 NPC 的关系。

理想效果：

```text
小芳：我记得小王经常点美式咖啡，而且他不太喜欢太甜的饮品。
```

### 6.4 与动物互动

用户靠近狗或猫后点击动物。

可选互动：

- 抚摸。
- 喂食。
- 靠近。
- 呼唤。

动物反应应根据性格、关系和当前状态变化：

- 亲人的狗会摇尾巴靠近。
- 胆小的猫可能躲开。
- 受惊的狗可能叫。
- 熟悉玩家后动物会更愿意接近。

动物反应也应产生事件和记忆。

### 6.5 世界现实规则

产品必须体现“世界不是背景图”。

示例：

- 玩家不能穿墙。
- 玩家不能穿过桌子、柜子、护栏。
- 玩家可以进入建筑内部。
- 玩家走向无护栏河流时会进入水中，并触发落水/溺水状态。
- 有护栏的河边会阻挡玩家进入。
- NPC 和动物也受这些规则约束。

## 8. 核心页面需求

### 8.1 小镇主页面

页面组成：

- 中央：2D 小镇地图。
- 顶部：小镇时间、运行状态、暂停/继续、速度控制。
- 左侧：NPC/动物列表。
- 右侧：选中实体详情。
- 底部：事件日志和对话日志。

必须展示：

- 当前时间。
- 当前选中角色状态。
- 当前行为。
- 当前地点。
- 最近事件。
- 最近对话。

### 8.2 NPC/动物详情面板

展示：

- 名称、年龄/种类、职业/习性。
- 性格标签。
- 当前状态。
- 当前行动。
- 当前情绪。
- 与玩家关系。
- 最近记忆摘要。
- 今日计划。

### 8.3 玩家角色创建页

字段：

- 名称。
- 性格。
- 外貌描述。
- 背景故事。

第一版可以使用默认 sprite，不强依赖捏脸系统。

### 8.4 记忆查看器

展示某个 NPC 的：

- 短期记忆。
- 长期记忆。
- 对话记忆。
- 每日总结。

用途：

- 让评审看到系统确实在记忆和利用上下文。

### 8.5 事件日志

展示世界中发生的关键事件：

- NPC 进入地点。
- 玩家与 NPC 对话。
- 动物反应。
- 物品交互。
- 危险触发。
- 记忆生成。

## 9. 智能体验需求

### 9.1 NPC 必须像“有生活的人”

NPC 不应该随机乱走。行为必须能解释：

- 为什么现在去这个地方。
- 为什么和这个人说话。
- 为什么记得某件事。
- 为什么对玩家态度变化。

前端可通过“当前想法/行动原因”展示一部分解释。

### 9.2 NPC 记忆必须可见

系统不能只在后台保存记忆。用户或评审需要能看到：

- 对话后新增了什么记忆。
- 哪些记忆被用于回答。
- 记忆重要度大概是多少。

### 9.3 LLM 不能成为黑盒随机输出

LLM 输出应转化为结构化行为：

- 回复文本。
- 情绪。
- 动作。
- 关系变化。
- 记忆写入。
- 后续行动。

## 10. 演示脚本

正式展示建议按以下流程：

### 场景 1：进入小镇

1. 打开网页。
2. 创建玩家角色。
3. 进入室外地图。
4. 展示当前时间、NPC 列表、事件日志。

要证明：

- 这是完整 Web 产品，不是命令行 demo。

### 场景 2：建筑内部地图

1. 玩家移动到咖啡店门口。
2. 点击或走到入口。
3. 进入咖啡店内部。
4. 展示室内家具、咖啡机、桌椅、NPC。

要证明：

- 世界不是单张平面图，有室内外空间。

### 场景 3：NPC 记忆对话

1. 玩家靠近小芳。
2. 询问：“小王喜欢喝什么？”
3. 小芳根据记忆回答。
4. 打开记忆面板展示相关记忆。

要证明：

- NPC 回复来自记忆和上下文，不是孤立聊天。

### 场景 4：动物互动

1. 玩家靠近豆豆。
2. 点击“抚摸”。
3. 豆豆开心摇尾巴。
4. 事件日志出现“玩家抚摸豆豆，豆豆很开心”。

要证明：

- 动物也是 Agent，会产生情绪和反应。

### 场景 5：环境后果

1. 玩家走到河边。
2. 从无护栏处进入水域。
3. 触发落水/溺水状态。
4. 有护栏位置无法进入。

要证明：

- 世界有现实规则，不是纯视觉地图。

### 场景 6：后续影响

1. 玩家再次和小芳对话。
2. 小芳提到刚才发生过的事情，或关系有所变化。
3. 展示新记忆。

要证明：

- 世界事件能影响后续行为。

## 11. 成功标准

### 11.1 产品体验标准

项目成功不是“能调用大模型”，而是满足：

- 用户能直观看到一个可探索的小镇。
- NPC 和动物有自主行为。
- 玩家能产生有意义的交互。
- 世界事件能被记录。
- NPC 后续行为能体现记忆。

### 11.2 技术展示标准

必须能向评审解释：

- 前端如何渲染地图和角色。
- 后端如何推进世界。
- NPC 如何做决策。
- LLM 如何通过 tool calling 影响世界。
- 记忆如何写入和召回。
- 玩家输入如何被理解和处理。

### 11.3 最小可验收标准

如果时间紧张，最小版本也必须具备：

1. Web 小镇地图。
2. 玩家可移动。
3. 室内外切换。
4. 6 个 NPC + 4 个动物实体显示。
5. 至少 2 个 NPC 有可解释日程行为。
6. 至少 1 个 NPC 能基于记忆回答玩家问题。
7. 至少 1 个动物能对玩家互动产生不同反应。
8. 事件和记忆能在前端展示。

---

## 12. 反偏离原则

开发过程中如果出现取舍，优先级如下：

1. **产品闭环优先于功能数量**：少做几个功能，也要保证设定、行动、交互、记忆、反馈闭环完整。
2. **可展示优先于内部复杂度**：复杂架构必须服务用户可见效果。
3. **可解释优先于随机智能**：NPC 行为需要能解释原因。
4. **真实世界规则优先于炫酷 UI**：碰撞、建筑、危险、动物反应比装饰动画更重要。
5. **稳定体验优先于模型自由发挥**：LLM 输出必须受结构化工具约束。

## 13. 最终产品效果描述

最终完成后，用户打开网页，会进入一个 2D 小镇。小镇里有街道、咖啡店、学校、杂货店、住宅、河流、护栏、家具、设施、猫和狗。用户可以创建自己的角色，在小镇里自由移动、进入建筑、点击角色和物品。

小镇中的 NPC 会按照自己的生活节奏行动：学生去学校，咖啡店员去上班，程序员去买咖啡，医生去诊所，杂货店老板看店。猫狗会闲逛、休息、靠近熟人、躲避陌生人。

玩家可以和 NPC 对话，也可以和动物互动。NPC 会根据自己的记忆、关系和当前场景回答，而不是每次都像第一次见面。动物也会根据性格和关系做出真实反应。

世界会记录发生过的事情。一次对话、一次抚摸、一次落水、一次帮助，都会成为事件和记忆，并可能影响后续行为。

这个产品最终要呈现的是：**一个由 AI Agent 驱动、玩家可参与、事件会沉淀为记忆、角色会持续变化的 Web 版 2D 生活小镇。**
