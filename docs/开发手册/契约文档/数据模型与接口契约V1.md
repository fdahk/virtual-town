# 数据模型与接口契约 V1

> 目的：作为前后端正式编码的第一版契约。后端 Pydantic、数据库模型、OpenAPI、前端 TypeScript 类型都以本文档为准。
>
> 修订记录：
> - V1.0（2026-04-30）首版。
> - V1.1（2026-04-30 阶段二）补齐：
>   - REST：新增 `GET /api/world/portals`、`GET /api/simulations/current`、
>     `GET /api/simulations/{id}/events`、`POST /api/agents/{id}/reflect`；
>     标注 `POST /api/world/interactions`、`PATCH /api/players/me/profile` 在 MVP 不实现。
>   - Schema：新增 `ToolCall` / `ToolResult` / `ToolError` / `AgentDecisionOutput` /
>     `ReflectionItem` / `ReflectionOutput` / `DailySummaryOutput`；
>     补齐 `PlayerInteractRequest.extra`、`PlayerTalkResponse.citations`、`Simulation.status` 枚举。
>   - WebSocket：补齐 `animal.reacted` / `llm.task_finished` / `memory.created` payload 定义。

## 1. 命名规范

### 1.1 ID 命名

所有业务主键使用 UUID，接口中统一使用字符串。

示例：

```json
{
  "agent_id": "8b7f8d2e-1a9f-4c5f-9f0a-000000000001"
}
```

### 1.2 时间

所有接口时间字段使用 ISO 8601：

```text
2026-04-30T08:00:00+08:00
```

### 1.3 坐标

坐标为 tile 坐标，不是像素坐标。

```json
{
  "x": 12,
  "y": 18
}
```

前端 Phaser 内部像素坐标由 `tile_size` 换算。

### 7.3 ToolCall / ToolResult / ToolError（LLM 工具调用）

由 LLM 决策管线产出，经 ToolExecutor 校验后执行。详细工具列表与参数 schema 见
`ToolCalling工具契约V1.md`，本节仅定义通用骨架。

```ts
interface ToolCall {
  tool: string;                       // 必须存在于 ToolRegistry
  arguments: Record<string, unknown>;
  confidence?: number;                // 0-1
  thought?: string;                   // 模型自述选择该工具的原因
}

interface ToolResult {
  tool: string;
  success: boolean;
  result: Record<string, unknown>;
  error?: ToolError | null;
  events: string[];                   // 产生的 WorldEvent id
  memory_candidates: Array<{
    memory_type: "event" | "thought" | "chat" | "summary";
    scope: "working" | "short_term" | "long_term";
    description: string;
    importance: number;
    keywords?: string[];
    emotional_valence?: number;
  }>;
}

interface ToolError {
  code:
    | "INVALID_ARGUMENTS"
    | "PERMISSION_DENIED"
    | "TARGET_NOT_FOUND"
    | "TARGET_NOT_REACHABLE"
    | "OUT_OF_RANGE"
    | "STATE_CONFLICT"
    | "TOOL_TIMEOUT"
    | "INTERNAL_ERROR";
  message: string;
  retryable: boolean;
}
```

### 7.4 AgentDecisionOutput（LLM Agent 决策输出）

LLM 调用 **`agent_decision` 模板**（`backend/app/prompts/agent_decision/v1.jinja2`，由 `prompts.render_prompt("agent_decision")` 加载）后必须严格返回此 JSON。
后端在 `app/llm/agent_decision.py` 中以 Pydantic v2 校验，校验失败 / 超时回退到规则版决策。

```ts
interface AgentDecisionOutput {
  thought: string;
  emotion?: string | null;
  tool_calls: ToolCall[];             // 至少 1 个、至多 3 个；超过 3 截断
  memory_writes: Array<{
    memory_type: "event" | "thought" | "chat" | "summary";
    description: string;              // <=400 字
    importance: number;               // 1-10
  }>;
}
```

### 7.5 ReflectionItem / DailySummaryOutput（反思与日结）

由 `app/domain/memory/reflection.py` 调用 **`reflection` / `daily_summary` 模板**
（分别为 `prompts/reflection/v1.jinja2`、`prompts/daily_summary/v1.jinja2`）产出。
同样有规则兜底（无需 LLM 也能跑）。

```ts
interface ReflectionItem {
  description: string;                // 高层结论 / 感受 / 决定
  importance: number;                 // 1-10，默认 5
  evidence_memory_ids: string[];      // 至少引用 2 条已存在的事件/对话记忆
}

interface ReflectionOutput {
  reflections: ReflectionItem[];
}

interface DailySummaryOutput {
  summary: string;                    // <=140 字
  highlights: string[];               // <=3 条
  mood?: string | null;
}
```

`PlayerInteractRequest`（实际实现）：

```ts
interface PlayerInteractRequest {
  object_id?: string;                 // 与 entity_id 二选一
  entity_id?: string;
  interaction_type: string;           // 例：pet/feed/call/scare/inspect/make_coffee
  extra?: Record<string, unknown>;    // 预留字段，前端不应直接拼装业务参数

```

`PlayerTalkResponse`（实际实现，新增 `citations` 字段）：

```ts
interface PlayerTalkResponse {
  conversation_id: string;
  reply: string;
  emotion?: string | null;
  memory_ids: string[];               // 本轮新写入的 NPC 记忆 id
  citations: Array<{                  // NPC 回复参考的记忆，用于 UI 透明化
    memory_id: string;
    description: string;
    score: number;
  }>;
}
```

## 10. 编码落地要求

1. 后端先实现 Pydantic schema，再生成 OpenAPI。
2. 前端通过 `openapi-typescript` 生成 API 类型。
3. WebSocket payload 在前后端各保留一份测试样例。
4. 数据库模型字段名必须和 Pydantic schema 尽量一致。
5. 任何字段改名必须同步修改本文档。
